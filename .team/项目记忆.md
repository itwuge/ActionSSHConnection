## 一、项目定位

| 项目 | 内容 |
| --- | --- |
| 项目名称 | ActionSSHConnection |
| 项目路径 | `c:\Users\Administrator\Desktop\ActionSSHConnection`（项目内引用一律写相对路径） |
| 远端仓库 | `https://github.com/itwuge/ActionSSHConnection.git`（**待推、远端尚未接入**：本地不配置 remote、不 push、不使用 gh 操作远端；本期先在本地完成再做推送） |
| 一句话定位 | **做 tmate 的替代品**：runner 主动反连到公网中转服务器，需求方从 SSH 客户端或网页进入该 runner，直接执行 `make menuconfig` 一类客制化交互操作，省掉本地编译环境。原定位「把 tmate 接进 GitHub Actions」已于 2026-11-09 因 tmate 不可用废止，见第五节决策表 |

| 使用路径 | 手动触发（`workflow_dispatch`）→ runner 起反向隧道，主动连到公网中转服务器 → 中转端给出 SSH 接入信息与网页入口 → 需求方用 SSH 客户端或浏览器进入 runner → 在 runner 上执行交互式命令 → 结束会话，runner 作业正常退出 |

## 四、验收口径

- 每条需求必须有可判定判据，写清通过条件与失败条件；只写「能用」「优化一下」视为无效。
- 验收报告须带证据链：操作步骤、日志或截图录屏路径、结论与判据逐条对应；无证据的结论一律写「未验证」，并写明原因与补验计划。
- 数字一律用实测值，禁估算；分头汇报的数量不得相加当作全局结论。
- 报告中不得断言实现状态；需核对实现时给出文件路径与行号。
- 凭据、token、私钥、登录态不得出现在日志、制品、构建摘要与仓库四类载体中（硬约束第 7 条），本项目尤其针对反向隧道接入凭据（原 tmate 会话 token 口径随定位变更废止）。
