# 项目记忆

本文件存放跨会话、跨岗位共享的项目事实与约定：项目目标、项目类型、启用编制、硬约束副本位置、验收口径、关键决策与裁决记录。岗位方法与单次会话过程不进本文件。

## 一、项目定位

| 项目 | 内容 |
| --- | --- |
| 项目名称 | ActionSSHConnection |
| 项目路径 | `c:\Users\Administrator\Desktop\ActionSSHConnection`（项目内引用一律写相对路径） |
| 远端仓库 | `https://github.com/itwuge/ActionSSHConnection.git`（**待推、远端尚未接入**：本地不配置 remote、不 push、不使用 gh 操作远端；本期先在本地完成再做推送） |
| 一句话定位 | 用 tmate 把 SSH 会话接入 GitHub Actions runner：触发工作流后，在 Actions 运行日志里取得 ssh 连接串与 `https://tmate.io/t/...` 网页会话地址，连进去即可在 runner 上直接执行 `make menuconfig` 一类客制化交互操作，省掉本地编译环境 |
| 交付形态 | GitHub Actions 工作流（`.github/workflows/` 下的 YAML）加配套说明文档；不产安装包、不做本地客户端、不建自建服务端 |
| 使用路径 | 手动触发（`workflow_dispatch`）→ 运行日志输出 tmate 连接串与网页地址 → 需求方用 SSH 客户端或浏览器进入 runner → 在 runner 上执行交互式命令 → 结束会话，runner 作业正常退出 |
| 本期明确不做 | 本地环境安装；正式构建制品；常驻或长期复用会话；生产凭据接入；图形界面 |

## 四、验收口径

- 每条需求必须有可判定判据，写清通过条件与失败条件；只写「能用」「优化一下」视为无效。
- 验收报告须带证据链：操作步骤、日志或截图录屏路径、结论与判据逐条对应；无证据的结论一律写「未验证」，并写明原因与补验计划。
- 数字一律用实测值，禁估算；分头汇报的数量不得相加当作全局结论。
- 报告中不得断言实现状态；需核对实现时给出文件路径与行号。
- 凭据、token、私钥、登录态不得出现在日志、制品、构建摘要与仓库四类载体中（硬约束第 7 条），本项目尤其针对 tmate 会话凭据。
