## 一、原设计与问题

设计书 v3 第 3.7 节把 `pubkey_credential_id` 列为九项白名单之一，工作流实现时据此把它写成仓库变量 `WEBAUTHN_CREDENTIAL_ID` 并在前置检查中列为必需项，缺值即 `precheck` 阶段失败。

该做法不成立：`pubkey_credential_id` 是浏览器在用户设备上完成 WebAuthn 注册时生成的公开凭据标识，随设备与站点绑定，**无法在任何一次运行之前预置为仓库变量**。把它设为必需项，等价于要求一个尚不存在的注册结果先存在，属设计错误。

## 二、更正

| 项目 | 更正后 |
|---|---|
| 字段性质 | 仍然是九项白名单字段之一，仍须出现在运行日志与构建摘要中，仍不得掩码 |
| 取值 | 允许为 `unset`。`unset` 是「尚未注册」的显式取值，视为已给出，不算字段缺失 |
| 仓库变量 | `WEBAUTHN_CREDENTIAL_ID` 改为可选；不再列入前置检查的必需变量 |
| SSH 通道 | 不受影响，`unset` 时照常建立会话 |
| 网页通道 | 首次进入时由浏览器完成设备注册并产生凭据标识；在此之前网页准入按设计书 v3 第 3.6 节的 WebAuthn 应用层挑战执行 |
| 判据一 | 通过条件中 `pubkey_credential_id` 取 `unset` 合法；失败条件中「缺项」不包含 `unset` |

## 三、影响面

- 工作流：`precheck` 去掉该变量的必需校验；路由字段输出 `pubkey_credential_id=${WEBAUTHN_CREDENTIAL_ID:-unset}`。
- 文档：`docs/使用说明.md` 的前提与字段说明同步。
- 其余八项字段的口径、判据二至判据七均不变。
- 中继侧无影响；`web/` 侧注册流程不在本次更正范围内，按原设计继续。

## 四、依据

- 决策来源：M01 于 2026-11-09 的裁决原文「`WEBAUTHN_CREDENTIAL_ID` 判定为设计错误，改为可选」。
- 技术依据：WebAuthn 凭据标识由认证器在注册仪式（`navigator.credentials.create`）中生成并由网站保存，服务端与仓库侧都无法预先获得。
