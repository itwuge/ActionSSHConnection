# 需求条目 需求-202611-001（v8）

> 本文件为同日 v8，在 v7 基础上新增**会话生命周期口径**：术语固定「**会话存活期内可反复进入，空闲或超时后结束**」。会话存活期内同一 `session_id` 可反复进入，断线后重连有效；失效条件仅三种：显式结束、作业/服务超时、空闲超时（新增，默认 10 分钟，可由工作流输入调整并写入设计）；失败尝试上限与时间窗保留（防爆破），超限只在窗口剩余时间内拒绝新尝试，不结束会话。v1–v7 均保留，未覆盖；冲突时以 v8 为准。
>
> **撤回记录**：v8 首稿曾写「一次性连接 / 一条连接 = 一次进入，进入即失效」，同日按用户要求撤回；理由是一次性会把项目锁死在 Actions 场景，无法作为工具箱复用到常驻服务器。撤回发生在提交前，未形成独立历史版本；本文件即撤回后的 v8 定稿。
>
> v7 的既有口径继续有效：`path_mode=direct` 为 Tailscale 覆盖网络直连（临时 auth key + 仅绑 `<100.x>` 的 sshd），`path_verified` 区分真直连与 DERP；`path_mode` 保持 `direct`/`relay` 两值。v6 的网页桥接落点、v5 的 `pubkey_credential_id` 可 `unset`、v4 的 `ssh_user`（relay 模式下含冒号的完整登录名）口径继续有效，v0.41.1 没有 ticket 概念。
>
> 必须如实写明：对称 NAT 下 Tailscale 会退到 DERP，此时数据经第三方，**不得声称纯 P2P**；`path_mode=direct` 只表示 tailnet 端点已发布，是否真直连以 `path_verified` 为准。固定口径：`path_mode=direct` 不等同纯 P2P，只有 `path_verified=direct` 才判定为点对点；`derp` 固定提示数据经 DERP 转发。所有 Tailscale 相关表述按「中继 / runner 由部署脚本自行安装配置」写，不依赖宿主预装。
>
> 本文件中的判据均为「应达到的状态」，实现是否达成须由 T01 实测并出证据链后判定；未取得证据前一律记「未验证」。设计书中标 `[待真机确认]` 的部分，判据通过前不得写成已具备能力。

## 四、期望结果

| 项目 | 填写内容 |
|---|---|
| 期望结果（做完之后用户能得到什么） | 显式触发的运行中，runner 主动反连到自建无状态中转，建立以 `session_id` 为唯一键的会话路由；运行日志原样给出中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间、网页地址、公钥凭据标识与当前路径九项常驻字段。同时尝试 Tailscale 直连：由部署脚本安装 Tailscale 客户端后，runner 用调用方仓库 Secret 中的临时 auth key 加入 tailnet，取得 `<100.x>` 地址并在该地址上起仅绑定该地址的 sshd；成功时日志给出 `path_mode=direct` 与 `direct_endpoint=<100.x>:<端口>`，首连后给出 `path_verified`（`direct`/`derp`/`unknown`）；不可用、auth key 缺失或加入失败时回落 `path_mode=relay`，`session_id` 不变。`ssh_user` 形态随路径：`relay` 为**含冒号的完整登录名**（形如 `<session_id>:<base64(节点地址)>`，冒号后是路由节点编码，属路由信息、不是凭据），`direct` 为专用非 root 用户（如 `runner`）。`pubkey_credential_id` 允许为 `unset`。需求方可用 SSH 进入 runner，也可用浏览器打开网页地址经公钥型认证进入同一终端进程（网页仍走中继桥接，不实现浏览器打洞），执行 `make menuconfig` 一类交互命令并即时看到输出，全程不依赖本地编译环境。对称 NAT 下 Tailscale 退到 DERP 时，日志与提示如实写明数据经第三方，**不声称纯 P2P**。**会话生命周期**：会话存活期内同一 `session_id` 可反复进入，断线后重连有效；两个入口各自可反复接入，不设消费位、不设「一次进入」限制。失效条件仅三种：一是显式结束（`exit`、主动取消或停止）；二是作业/服务超时（工作流 `timeout-minutes` 55 分钟、会话最大时长 45 分钟）；三是空闲超时（新增，默认 10 分钟，可由工作流输入调整，范围 1–45 分钟，判定为连续无客户端连接且无终端输入/输出）。任一失效后中继路由回收，两个入口同时失效，原连接信息重连被拒，提示「会话已结束，请重新发起会话获取新的连接串」；作业正常收尾。进入前的失败尝试保留次数上限与时间窗（候选 5 次/10 分钟，`[待真机确认]`），超限只在窗口剩余时间内拒绝新尝试（提示「尝试次数超过上限，请稍后再试」），不结束会话，窗口滑过后恢复。中继进程重启后不残留任何路由与会话文件 |
| 不包含什么（本次边界，明确排除项） | 不做会话录制与回放；不在本地安装任何环境；不产出正式构建制品、不替代既有 CI 构建流水线；不做常驻或长期复用会话（会话存活期内允许反复进入与断线重连，不属于会话复用）；不接入生产凭据与线上通知通道；中转不放业务逻辑、不承载访客认证、不做访问判定、不落盘会话状态、不承担限流与审计；不引入 tmate 式连接串、upterm 默认不限定公钥模式、`sshx`、网页 URL 带一次性 token、口令认证（含 `ttyd` 口令）、OAuth `client_secret` 或任何长期密钥落中转；不承诺 Tailscale 打洞一定成功，不声称纯 P2P（对称 NAT 下会退到 DERP，数据经第三方）；不引入 ZeroTier，也不依赖宿主预装覆盖网络（Tailscale 由部署脚本安装）；不使用 Tailscale SSH（避免第二条认证路径）；不改用 `uptermd` 的 SSH-over-WS 承载自定义帧（协议不匹配） |

## 五、验收判据（必须可判定）

| 序号 | 判据描述 | 通过条件 | 失败条件 |
|---|---|---|---|
| 1 | 会话建立且日志九项常驻字段可用 | 一次显式触发的运行日志中，同时出现且可原样复制：中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间、网页地址、公钥凭据标识、当前路径（`path_mode`）九项常驻字段；`pubkey_credential_id` 允许取值为 `unset`（视为已给出且合法，不属缺失）；`ssh_user` 形态随 `path_mode`：`relay` 为**含冒号的完整登录名**（形如 `<session_id>:<base64(节点地址)>`），冒号后的路由节点编码属路由信息、不作凭据处理，但不得截断或改写；`direct` 为专用非 root 用户（如 `runner`，无冒号）；`path_mode=direct` 时另须出现 `direct_endpoint`（格式 `<100.x>:<端口>`，只填 tailnet 地址），首连后须出现 `path_verified`（`direct`/`derp`/`unknown`）；`path_mode=relay` 时不得出现 `direct_endpoint` 与 `path_verified`；路由行在运行日志与构建摘要中均原样可读 | 九项常驻缺任一项（`pubkey_credential_id` 为 `unset` 不算缺项）；`direct` 缺 `direct_endpoint` 或 `relay` 出现 `direct_endpoint`；`direct_endpoint` 填公网地址或含凭据；任一字段被掩码成 `***`（**掩码即判据一失败**）；`ssh_user` 在 `relay` 下只输出冒号前片段、被截断为不可登录形式；地址被截断、改写为不可用形式 |
| 2 | 可登入 runner 并执行 TUI，且会话保持可进入 | 用判据一给出的字段在本地 SSH 客户端登录成功（`path_mode=direct` 时用 `<100.x>:<端口>` 与对应 `ssh_user`，`relay` 时用中继入口与含冒号登录名），登入后执行 `make menuconfig`（验证样例）能进入菜单界面并接受键位输入；**首次成功进入后会话保持可进入**：断开 SSH 客户端后用原连接信息重连成功，且 `session_id` 不变（反复进入与重连的完整判定见判据八） | 认证失败或被拒；登录后立即断开；交互命令无法启动或无输出；断线后用原连接信息无法重连 |
| 3 | 会话结束作业收尾且结束后重连被拒 | 会话被结束后，本次工作流运行状态为成功；用原连接信息再次连接（SSH 的直连/中继入口与网页入口分别验证）均被拒绝；显式结束、作业/服务超时、空闲超时三种失效条件分别触发后均按此判定（与判据八共同验证）；路由回收时长有实测秒数记录；tailnet 临时节点随 runner 销毁 | 任一入口仍可连接；作业长时间挂起直至超时失败；路由残留需人工清理；tailnet 节点残留；无回收时长实测记录 |
| 4 | 凭据不进四类载体且中继无凭据 | 对运行日志、制品、构建摘要、仓库逐一检索，不存在私钥、口令、一次性 token、GitHub token，也不存在服务身份密钥原文；`ssh_user` 冒号后的路由节点编码属路由信息、**不属凭据**，允许出现在四类载体，但不得被当作可复用凭据；该编码不能用于换取登录，无对应会话路由即不可达；Tailscale 临时 auth key 与 tailnet 节点私钥**不得**出现在运行日志、制品、构建摘要、仓库；`direct_endpoint`、`path_verified` 属路由信息，允许出现在四类载体；Tailscale 节点元数据可记录但不得含 key 值；中继侧无任何用户私钥、口令、一次性 token 或长期 bearer；网页桥接进程日志**不得包含帧负载或断言原文**；失败计数、时间窗起点与空闲计时不得写入日志或落盘；会话前后对中转机 `/tmp`、`/var`、systemd 工作目录做文件清单比对，差异逐条可解释 | 任一载体出现上述凭据（含 Tailscale auth key 或节点私钥）；中继存有用户私钥或口令；把路由节点编码登记为凭据或当作登录凭据使用；桥接日志出现帧负载、断言原文或凭据；失败计数或空闲计时出现在日志或磁盘；中转机出现无法解释的新增文件残留；host key / TLS key 未登记或权限非 `0600` |
| 5 | 网页入口可用且认证为公钥型，存活期内可反复进入 | 打开判据一给出的网页地址后，未经设备私钥签名（WebAuthn 断言）不得进入；完成设备内签名并经验签后能进入同一终端进程并操作 TUI；**会话存活期内可反复进入**：通行密钥注册成功并进入后，同一浏览器再次打开、刷新、断线重连均有效；进入路径为「浏览器 → `certbot-nginx:443` → 桥接 → runner 反连 WS → `web_admission.py`」，桥接不解析帧；网页地址与 WS 路径中不含一次性 token、口令、公钥原文等任何可复用凭据；会话失效（显式结束、作业/服务超时、空闲超时）后该入口立即失效并提示「会话已结束」；**再起新会话后，用旧 `session_id` 重试仍被拒** | 无签名即可进入；网页地址或 WS 路径携带可复用凭据；进入后无法操作 TUI；会话存活期内同一链接无法再次进入；会话结束后网页入口仍可用；旧 `session_id` 能串入新会话 |
| 6 | 中继无状态 | 中继进程（`uptermd` 与网页桥接）重启后：无残留路由（按原 `session_id` 连接返回「路由不存在」）、无会话文件（文件清单无新增）、无审计账本需要伪造痕迹；网页桥接的 `session_id → runner_ws` 内存映射清空；重启前正在进行的会话被中断，且中断可观测（断开时间有实测秒数），不出现会话「自动恢复」但状态不一致的情况 | 重启后仍能按原 `session_id` 进入；出现新增会话文件或审计记录；桥接重启后仍有配对残留；重启后旧会话表现为部分可用或状态错乱 |
| 7 | 连接路径、直连与回落 | 日志出现 `path_mode`，取值只能是 `direct` 或 `relay`；`direct` 分支：`direct_endpoint` 为 `<100.x>:<端口>` 且与实际连接一致，首连后 `path_verified` ∈ `direct`/`derp`/`unknown`，提示分别为「直连已建立」「直连未建立，数据经 Tailscale DERP 中继转发」「直连待验证，尚未确认是否经过 DERP」；`relay` 分支：直连不可用、auth key 缺失或加入失败时出现 `path_mode=relay`，`session_id` 与直连尝试前相同，提示为「直连未建立，已切换到中继转发」；三种形态的九项常驻字段一致，仅条件字段与取值不同；`path_verified=derp` 时不得声称纯 P2P；tailnet 临时节点随 runner 销毁；提示与日志均不含任何凭据 | 无 `path_mode` 或取值非法；`direct` 缺 `direct_endpoint`；把 `path_verified=derp` 写成纯 P2P 或「直连已建立」；回落重建会话、更换 `session_id`，导致用户需重新取连接信息；提示语含凭据；三种形态字段集合不一致导致判据一无法判定；把托管 runner 上的 DERP 或 `relay` 写成真直连 |
| 8 | 会话存活期内反复进入、三种失效条件与失败上限 | 同一 `session_id` 在会话存活期内可任意次进入：断开 SSH 客户端后用原连接信息重连成功；网页关闭或刷新后再次打开经断言进入成功；两个入口各自可反复接入，不设消费位；失效条件**仅三种**且分别实测：① 显式结束（`exit`/主动取消/停止）后立即失效；② 作业/服务超时（工作流 `timeout-minutes` 55 分钟、会话最大时长 45 分钟）到达后失效；③ 空闲超时（默认 10 分钟，可调 1–45 分钟）到达后失效，默认值写入设计并有实测记录；三种失效后中继路由回收，原 `session_id` 的两个入口均被拒并提示「会话已结束，请重新发起会话获取新的连接串」；进入前的失败尝试有次数上限与时间窗（候选 5 次/10 分钟，`[待真机确认]`），超限只在该窗口剩余时间内拒绝新尝试（提示「尝试次数超过上限，请稍后再试」），窗口滑过后恢复，且**不结束会话**；失败计数、时间窗与空闲计时不落盘、不进日志、不进四类载体；中继不计数、不判定；未出现第四种失效条件 | 会话存活期内断线无法重连或同一链接无法再次进入；出现第四种失效条件；仅因断开客户端即结束会话；空闲超时缺失或默认值未写入设计/无实测；失败超限后永久拒绝或直接结束会话；失败计数或空闲计时被写入日志或落盘；中继承担计数或判定；失效提示未表达「会话已结束」 |

> 判据 1 至 4 由 T01 在真机运行 GitHub Actions 与已部署中转机上取证；判据 4、5、6 由 S01 与 T01 共同核查；判据 8 由 T01 取证、S01 复核（中继无状态边界与失败计数/空闲计时不落盘）；判据 7 的 `relay` 分支与托管 runner 上的 `derp` 分支在托管 runner 取证，真直连（`path_verified=direct`）须实测并写明取证环境；auth key 过期、DERP 识别方式、tailnet 内 22 端口可达性等 8 项按 `.team/records/设计更正-直连路径-20261109.md` 第七节真机确认。取得证据前一律记「未验证」，不得记「已通过」。固定口径：`path_mode=direct` 不等同纯 P2P，只有 `path_verified=direct` 才判定为点对点；`derp` 固定提示数据经 DERP 转发。
