# 设计更正：真正的 P2P 直连路径（Tailscale，2026-11-09）

| 项目 | 内容 |
|---|---|
| 文件性质 | 设计更正，不改已有中继与网页结论；只把「直连路径」从 TCP 探针占位改为可实施的覆盖网络直连 |
| 依据 | ① GitHub 托管 runner 在 NAT 后、无入站端口，直连必须靠覆盖网络打洞；② 生产机 `47.109.32.249` 已运行 ZeroTier（9993），仅作参照，不引入；③ 现有 9 字段与判据已含 `path_mode`，回落规则要求不换 `session_id`；④ 当前 `path_mode=direct` 只是 TCP 探针占位，不是真直连 |
| 主笔 / 会签 / 拍板 | M03 架构师 / P08、G01、O01、T01、S01 / M01 |
| 结论 | 直连实现用 Tailscale：runner 侧用临时 auth key 加入 tailnet，在 tailnet 地址上起仅绑定该地址的 sshd；日志输出 `path_mode=direct` 与 `direct_endpoint=<100.x>:<端口>`；打洞不可用、auth key 缺失或加入失败回落 `path_mode=relay`，`session_id` 不变。对称 NAT 下 Tailscale 退到 DERP 时，数据经第三方，**不得声称纯 P2P** |
| 历史版本 | 设计书 v1、v2 保留不改；设计书 v3 对应章节同步；需求条目出 v7，v1–v6 保留 |

## 一、已核实前提与现状

| 序号 | 事实 | 对设计的影响 |
|---|---|---|
| 1 | GitHub 托管 runner 在 NAT 后、无入站端口 | 直连不能靠 runner 公网监听；必须由 runner 主动加入覆盖网络，再由对端经覆盖网络地址访问 |
| 2 | 生产机 `47.109.32.249` 已运行 ZeroTier（9993） | 只作「覆盖网络可行」的参照；本项目不引入 ZeroTier，避免两套覆盖网络与两套凭据 |
| 3 | 现有 9 字段与判据已含 `path_mode`；回落要求不换 `session_id` | 字段与回落骨架保留；新增 `direct_endpoint` 与条件验证字段 `path_verified`，`session_id` 在 `path_mode=direct`（含 `path_verified=derp`）与 `path_mode=relay` 之间不变 |
| 4 | 当前 `path_mode=direct` 只是 TCP 探针占位，不是真直连 | 本更正把「探针成功」改为「tailnet 路径可用且首连后实测路径」，避免把可达性探测当成 P2P |
| 5 | `session_id`、SSH 通道、网页中继桥接均已定 | 本更正只动 SSH 直连面；网页仍走中继桥接，判据五不变 |

## 二、两条数据面的边界

| 维度 | 中继面（现有，保留） | 直连面（本更正新增） |
|---|---|---|
| 入口 | 用户 SSH 到中继 `22`，由 `uptermd` 转发到 runner 反向连接 | 用户 SSH 到 tailnet 地址 `<100.x>:<端口>`，runner 侧 sshd 仅绑定该地址 |
| 谁终结认证 | runner 侧内嵌 sshd 验访客公钥；中继不验、不判 | runner 侧 tailnet sshd 验访客公钥；Tailscale/WireGuard 提供网络层节点身份；中继不在路径上 |
| 谁持有凭据 | 中继不持有用户私钥/口令/长期 bearer；runner 持有会话侧公钥材料 | runner 持有临时 tailnet 节点密钥（随 runner 销毁）；用户设备持有自己的 tailnet 设备身份；调用方仓库 Secret 持有临时 auth key；中继不持有任何直连凭据 |
| 数据经过 | 阿里云成都 ECS（2 vCPU / 2 GiB / 3 Mbps） | 打洞成功：两端直接；对称 NAT：Tailscale DERP（第三方）；两种情况都不经本项目中继 |
| 数据面是否可被中继看见 | 是（中继转发字节，但无凭据、无落盘） | 否；但 DERP 情况下第三方可见连接元数据，数据仍由 WireGuard 端到端加密 |
| 失效方式 | 中继进程停止/重启 → SSH 入口断开 | tailnet 节点下线、auth key 过期、runner 销毁 → 直连入口失效；中继面仍可回落 |
| 与网页的关系 | 网页通道继续走中继桥接，不受本更正影响 | 直连面**只承载 SSH**，不承载网页终端；`direct_endpoint` 与网页 URL 无关 |

## 三、直连面 sshd 加固要求

| 项目 | 要求 | 判定 |
|---|---|---|
| 监听地址 | `ListenAddress <100.x 地址>`，只绑 tailnet 地址；不绑 `0.0.0.0`、不绑公网地址 | `ss -lntp` 只见 `<100.x>:<端口>`；公网网卡无该端口 |
| 监听端口 | 候选 `22` 或 `2222`，写入 `direct_endpoint` 的端口段；推荐 `2222` 避开 runner 既有 sshd 端口冲突 | 端口与 `direct_endpoint` 一致；`[待真机确认]` runner 镜像是否已占用 |
| 口令认证 | `PasswordAuthentication no`、`KbdInteractiveAuthentication no`、`PermitEmptyPasswords no` | `sshd -T` 输出为 `no` |
| root 登录 | `PermitRootLogin no`；使用专用非 root 用户（如 `runner`）登录，需要时再 `sudo` | `sshd -T` 为 `no`；登录用户非 root |
| 公钥来源 | `AuthorizedKeysFile` 指向会话临时文件；启动时从 GitHub 公钥接口拉取指定账号的公钥，校验 TLS、设超时、失败即不启动；每次会话重新拉取，不缓存到 runner 之外 | 文件权限 `0600`、属主正确；拉取失败时 sshd 不监听；`[待真机确认]` 具体接口与账号来源 |
| 转发与旁路 | `AllowTcpForwarding no`、`AllowAgentForwarding no`、`X11Forwarding no`、`PermitTunnel no`、`GatewayPorts no` | `sshd -T` 逐项为 `no` |
| 会话限制 | `MaxSessions 1`、`MaxAuthTries 3`、`LoginGraceTime 30`、`ClientAliveInterval` 与 `ClientAliveCountMax` 设上限 | 配置可指认；超限断开 |
| 生命周期 | sshd 作为作业子进程启动，作业结束即杀；`trap` 清理；`tailscale down`/`logout` 使节点下线；不写 systemd 常驻单元 | 作业结束后 `ss` 无监听、`tailscale status` 无该节点 |
| 防火墙 | nftables 只允许 `tailscale0` 接口到该端口；公网接口一律拒绝 | `nft list ruleset` 可指认；公网扫描不可达 |
| host key | 每轮生成临时 host key，不落仓库；用户首次连接使用 `StrictHostKeyChecking=accept-new`，依赖 Tailscale 节点身份与 WireGuard 加密 | `[待真机确认]` 是否需要在日志额外给 host key 指纹；本期不新增字段，先按 `accept-new` 取证 |
| 其他 | 不使用 Tailscale SSH（`--ssh=false`），避免出现第二条认证路径；不广告 subnet route、不广告 exit node | `tailscale status --json` 与 ACL 可指认 |

## 四、密钥治理

| 项目 | 做法 | 说明 |
|---|---|---|
| 临时 auth key | 调用方仓库 GitHub Actions Secret 保存；`ephemeral=true`、`preauthorized=true`、限定 `tag:actssh-runner`、有效期候选 24 小时；**不进日志、制品、构建摘要、仓库** | Secret 本身是凭据存储，不算四类载体；日志中只出现 `path_mode`/`direct_endpoint`，不出现 key 值 |
| 节点 | 每轮 `tailscale up --auth-key=file:<临时文件> --hostname=actssh-<run_id> --advertise-tags=tag:actssh-runner --ephemeral --ssh=false`；节点随 runner 下线自动移除 | `[待真机确认]` ephemeral 节点的实际清理时延 |
| tag 与 ACL | 只给 `tag:actssh-runner`；ACL 只允许调用方身份访问 `tag:actssh-runner` 的 SSH 端口，其余端口与网段一律拒绝；不建 subnet route、不建 exit node | ACL 变更属对外承诺与合规，按四类升级第 2 类报用户 |
| 过期时间 | auth key 有效期候选 24 小时；到期后加入失败 → 回落 `path_mode=relay` 并输出固定提示；节点 key 随节点销毁 | 过期行为 `[待真机确认]`；Secret 轮换写入运维手册 |
| 泄露处置 | ① 在 Tailscale 管理台立即 revoke 该 auth key；② 删除所有带 `tag:actssh-runner` 的临时节点；③ 轮换调用方仓库 Secret；④ 查 tailnet 审计与 runner 日志，确认 key 未进四类载体；⑤ 用新 key 重跑，确认 `path_mode` 与 `direct_endpoint` 正常；⑥ 若节点 key 也可能泄露，删除节点并重新生成 | 处置步骤写入运维手册；不在日志打印 key 或节点密钥 |
| 用户侧凭据 | 用户设备需在同一个 tailnet（或由用户自己的 Tailscale 身份接入）；设备私钥只在用户设备 | `[待真机确认]` 用户设备是否已加入；未加入时直连不可达，只能走中继 |
| 生产机 ZeroTier | 仅作参照，不复用其身份、网络或密钥 | 避免两套覆盖网络交叉 |

## 五、回落判定与固定提示语

### 5.1 判定顺序

| 步骤 | 判定 | 结果 |
|---|---|---|
| 1 | 调用方仓库 Secret 是否存在 `TS_AUTHKEY` | 缺失 → `path_mode=relay`，输出中继提示 |
| 2 | `tailscale up` 是否在超时内成功（候选 30 秒） | 失败/超时 → `path_mode=relay`，输出中继提示 |
| 3 | 是否取得 tailnet IPv4（`100.64.0.0/10`） | 未取得 → `path_mode=relay` |
| 4 | sshd 是否成功仅绑定该地址并监听 | 失败 → `path_mode=relay` |
| 5 | 以上均成功 → 输出 `path_mode=direct` 与 `direct_endpoint`；首连后判定 `path_verified` | `direct`：直连；`derp`：Tailscale DERP；`unknown`：尚未连接或无法判定 |

### 5.2 `path_mode` 合法组合

| `path_mode` | `direct_endpoint` | `path_verified` | 数据面 | 用户提示（固定文案） |
|---|---|---|---|---|
| `direct` | 必填，`<100.x>:<端口>` | `direct` | tailnet 直连，不经第三方中继 | 「直连已建立」 |
| `direct` | 必填，`<100.x>:<端口>` | `derp` | Tailscale DERP（第三方），**不是纯 P2P** | 「直连未建立，数据经 Tailscale DERP 中继转发」 |
| `direct` | 必填，`<100.x>:<端口>` | `unknown` | 尚未连接或无法判定 | 「直连待验证，尚未确认是否经过 DERP」 |
| `relay` | 不出现 | 不出现 | 本项目中继 | 「直连未建立，已切换到中继转发」 |

约束：

- `path_mode=relay` 时 `direct_endpoint` 不得出现；`path_mode=direct` 时 `direct_endpoint` 必须出现。
- `path_verified` 只在 `path_mode=direct` 且发生首连后出现；未连接时可为 `unknown`。
- `path_mode=direct` 不等于「纯 P2P」；只有 `path_verified=direct` 才能说直连，`path_verified=derp` 必须明确第三方中继。
- 任何情况下 `session_id` 不变；回落不重建会话、不要求用户重新获取连接信息。
- 提示语不得出现 auth key、节点密钥、私钥、口令、一次性 token；允许出现地址、端口、`session_id`、`path_mode`、`path_verified`。

## 六、对 9 字段与判据的影响

### 6.1 字段

| 字段 | 变化 | 说明 |
|---|---|---|
| 原 9 项 | 保留 | `relay_host`/`port` 仍指中继入口，用于回落；direct 模式下中继信息照常给出 |
| `ssh_user` | 语义随路径 | `path_mode=direct` 时为专用非 root 用户（如 `runner`，无冒号）；`path_mode=relay` 时仍为 `<session_id>:<base64(节点地址)>`，必须原样完整 |
| `direct_endpoint` | **新增，条件字段** | 仅 `path_mode=direct` 出现，格式 `<100.x>:<端口>`，属路由信息，不是凭据；不得填公网地址 |
| `path_verified` | **新增，条件字段** | 仅 `path_mode=direct` 且首连后出现，取值 `direct`/`derp`/`unknown`；属路由信息 |
| `web_url` | 不变 | 网页仍走中继桥接，与直连面无关 |

### 6.2 判据

| 判据 | 影响 | 处置 |
|---|---|---|
| 一（字段可用） | 由「9 项齐备」扩为「9 项常在 + direct 模式下 `direct_endpoint` 必填 + 首连后 `path_verified` 出现」；`ssh_user` 形态随 `path_mode` 校验 | 更新为 v7 判据一 |
| 四（四类载体零凭据） | 补「auth key 不进四类载体」；`direct_endpoint`、`path_verified` 属路由信息可记录；Tailscale 节点元数据可记录但不得含 key | 更新为 v7 判据四 |
| 五（网页入口） | **不变**；网页仍走中继桥接，直连面不承载网页 | 保持原判据 |
| 七（连接路径与回落） | 取值保持 `direct`/`relay`，新增条件字段 `path_verified`（`direct`/`derp`/`unknown`）区分真直连与 DERP；补 `direct_endpoint`、固定提示语、`session_id` 不变、DERP 不得声称纯 P2P、节点随 runner 销毁 | 更新为 v7 判据七 |

## 八、影响与回滚

| 项目 | 内容 |
|---|---|
| 模块 | 新增「直连路径（Tailscale 接入 + tailnet sshd）」模块，P08 主责、G01 管 Secret、O01 管运维、T01 取证、S01 审查；中继与网页模块不变 |
| 批次 | 新增第 6 批「直连路径」，前置第 3 批（SSH 通道）；产物含 `scripts/start_direct_path.sh`、`scripts/verify_direct_path.sh`、工作流步骤与验收报告 |
| 风险 | ① 打洞成功率不稳定；② DERP 被误写成 direct；③ auth key 泄露/过期；④ tailnet sshd 绑定过宽；⑤ 用户设备未加入 tailnet；⑥ 第三方 DERP 带来合规与可用性依赖 |
| 回滚 | 去掉工作流中的 Tailscale 步骤与 tailnet sshd，保留中继面；`path_mode` 固定 `relay`；清理 tailnet 临时节点与 Secret；判据七只验 relay 分支 |
| 回滚判据 | SSH 中继通道判据一至四仍通过；无 tailnet 监听与节点残留；日志不再出现 `direct_endpoint`/`path_verified` |

## 九、结论与未定项

- 直连实现用 Tailscale，不再用 TCP 探针冒充直连；`path_mode=direct` 只在 tailnet 路径可用时出现，首连后以 `path_verified` 区分直连与 DERP。
- 中继面与网页面结论不变；网页仍走中继桥接，直连面只承载 SSH。
- 对称 NAT 下 Tailscale 退 DERP，数据经第三方，**不得声称纯 P2P**；`path_verified=derp` 必须如实记录并提示。
- 第七节 8 项全部 `[待真机确认]`；未取证前不得写成已具备能力。
