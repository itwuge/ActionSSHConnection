## 三、现状与痛点

| 项目 | 填写内容 |
|---|---|
| 现状（目前怎么做） | 两条路：一是在本地安装整套工具链后跑 `make menuconfig`；二是直接编辑配置文件文本，推 CI 靠构建结果反推是否正确。原用 tmate 取会话的方式已失效 |
| 痛点（哪里不行、造成什么后果） | 本地环境搭建与维护成本高、占用磁盘、换机器要重来；文本直改看不到菜单依赖关系，易改出互斥项冲突，每次验证要等一轮完整构建；tmate 不可用后，runner 侧交互入口整体缺失；无浏览器侧入口，临时设备上无法操作 |
| 已有替代方案及其不足 | 本地容器或虚拟机：仍需下载镜像与工具链，磁盘与网络成本照旧；直接引用第三方会话服务：把第三方代码、凭据处理方式与暴露面一并引入，令牌与会话地址不受本项目控制，日志出现凭据时无本地规范约束；有状态中继：需在中转落盘会话、承担认证判定与审计，中转一旦失陷影响面大 |

## 四、期望结果

| 项目 | 填写内容 |
|---|---|
| 期望结果（做完之后用户能得到什么） | 显式触发的运行中，runner 主动反连到自建无状态中转，建立以 `session_id` 为唯一键的会话路由；运行日志原样给出中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间、网页地址、公钥凭据标识与当前路径九项。需求方可用 SSH 进入 runner，也可用浏览器打开网页地址经公钥型认证进入同一终端进程，执行 `make menuconfig` 一类交互命令并即时看到输出，全程不依赖本地编译环境。连接建立先尝试直连打洞，失败即回落中继，回落不更换 `session_id`。会话结束后两个入口同时失效，原信息重连被拒；中继进程重启后不残留任何路由与会话文件 |
| 不包含什么（本次边界，明确排除项） | 不做会话录制与回放；不在本地安装任何环境；不产出正式构建制品、不替代既有 CI 构建流水线；不做常驻会话或会话复用；不接入生产凭据与线上通知通道；中转不放业务逻辑、不承载访客认证、不做访问判定、不落盘会话状态、不承担限流与审计；不引入 tmate 式连接串、upterm 默认不限定公钥模式、`sshx`、网页 URL 带一次性 token、口令认证（含 `ttyd` 口令）、OAuth `client_secret` 或任何长期密钥落中转；不承诺 GitHub 托管 runner 上打洞一定成功（托管 runner 无入站端口，纯 P2P 通常不成立，打洞仅作优化项） |

## 五、验收判据（必须可判定）

| 序号 | 判据描述 | 通过条件 | 失败条件 |
|---|---|---|---|
| 1 | 会话建立且日志九项字段可用 | 一次显式触发的运行日志中，同时出现且可原样复制：中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间、网页地址、公钥凭据标识、当前路径（`path_mode`）九项；路由行在运行日志与构建摘要中均原样可读 | 九项缺任一项；或路由行中任一字段被掩码成 `***`（**掩码即判据一失败**）；或地址被截断、改写为不可用形式 |
| 2 | 可登入 runner 并执行 TUI | 用判据一给出的字段在本地 SSH 客户端登录成功，登入后执行 `make menuconfig`（验证样例）能进入菜单界面并接受键位输入 | 认证失败或被拒；登录后立即断开；交互命令无法启动或无输出 |
| 3 | 会话结束作业收尾且原信息重连被拒 | 会话被结束后，本次工作流运行状态为成功；用原连接信息再次连接（SSH 与网页两个入口分别验证）均被拒绝；路由回收时长有实测秒数记录 | 任一入口仍可连接；作业长时间挂起直至超时失败；路由残留需人工清理；无回收时长实测记录 |
| 4 | 凭据不进四类载体且中继无凭据 | 对运行日志、制品、构建摘要、仓库逐一检索，不存在私钥、口令、一次性 token、GitHub token，也不存在服务身份密钥原文；中继侧无任何用户私钥、口令、一次性 token 或长期 bearer；会话前后对中转机 `/tmp`、`/var`、systemd 工作目录做文件清单比对，差异逐条可解释 | 任一载体出现上述凭据；中继存有用户私钥或口令；中转机出现无法解释的新增文件残留；host key / TLS key 未登记或权限非 `0600` |
| 5 | 网页入口可用且认证为公钥型 | 打开判据一给出的网页地址后，未经设备私钥签名（WebAuthn 断言）不得进入；完成设备内签名并经验签后能进入同一终端进程并操作 TUI；网页地址与 WS 路径中不含一次性 token、口令、公钥原文等任何可复用凭据；会话结束后该入口立即失效 | 无签名即可进入；网页地址或 WS 路径携带可复用凭据；进入后无法操作 TUI；会话结束后网页入口仍可用 |
| 6 | 中继无状态 | 中继进程重启后：无残留路由（按原 `session_id` 连接返回「路由不存在」）、无会话文件（文件清单无新增）、无审计账本需要伪造痕迹；重启前正在进行的会话被中断，且中断可观测（断开时间有实测秒数），不出现会话「自动恢复」但状态不一致的情况 | 重启后仍能按原 `session_id` 进入；出现新增会话文件或审计记录；重启后旧会话表现为部分可用或状态错乱 |
| 7 | 连接路径与回落 | 日志出现 `path_mode`，取值只能是 `direct` 或 `relay`；`relay` 分支：打洞在超时内被判失败、回落中继后 `session_id` 与阶段一相同、用户提示为「直连未建立，已切换到中继转发」；`direct` 分支：日志为 `path_mode=direct` 且直连对端地址与实际连接一致，提示为「直连已建立」；两条路径的九项字段白名单一致，仅取值不同；提示与日志均不含任何凭据 | 无 `path_mode` 或取值非法；回落重建会话、更换 `session_id`，导致用户需重新取连接信息；提示语含凭据；两条路径字段集合不一致导致判据一无法判定；把托管 runner 上的预期 `relay` 写成 `direct` |

> 判据 1 至 4 由 T01 在真机运行 GitHub Actions 与已部署中转机上取证；判据 4、5、6 由 S01 与 T01 共同核查；判据 7 的 `relay` 分支在托管 runner 取证，`direct` 分支须在自建 runner 或同 NAT 环境取证，取证环境须写入报告。取得证据前一律记「未验证」，不得记「已通过」。
