## 二、总目标与边界

做 tmate 的替代品：GitHub Actions runner 主动反连公网中转服务器建立会话，需求方用 SSH 进入该 runner，直接执行 `make menuconfig` 一类交互式操作，省掉本地编译环境。

| 项目 | 内容 |
| --- | --- |
| 一期范围 | 只做 SSH 通道：中转端自托管 uptermd，runner 端用 action-upterm 反连，SSH 进入 runner |
| 中转候选 | 阿里云成都 ECS，规格与带宽按 `资源基线.md` 第一节；域名按 `资源基线.md` 第二节（`wuge.fun`），中转会话域名 `relay.wuge.fun` |
| 二期范围 | 网页通道，**仅列为待评估**，本方案不定选型、不定接口 |
| 不在范围 | 见第六节「明确排除」 |

## 三、一期架构（SSH 通道）

### 3.1 拓扑与角色

```text
需求方(SSH 客户端)
      │  ssh -p 22 <用户名>@relay.wuge.fun
      ▼
阿里云成都 ECS（中转端：uptermd，systemd 常驻，监听 0.0.0.0:22）
      ▲
      │  runner 主动发起反连（ssh://relay.wuge.fun:22）
GitHub Actions runner（action-upterm 拉起的 upterm 客户端 + 会话）
```

链路方向由 runner 主动发起，中转端不主动连 runner；需求方进的是「会话」而非直连 runner 的公网地址。

### 3.2 中转端（uptermd）

| 项目 | 设计要求 |
| --- | --- |
| 运行方式 | 自托管 `uptermd`，systemd 常驻 |
| 监听 | `0.0.0.0:22` |
| 端口冲突处理 | 系统 OpenSSH 迁移到 `127.0.0.1:22022`，或仅放行白名单来源；二者取其一，避免与 uptermd 抢 22 |
| metrics | 只绑 `127.0.0.1:9100`，不对公网暴露 |
| 主机密钥 | 放 `/var/lib/uptermd`，权限 `0600`，属主 `upterm` |
| 授权公钥 | `/etc/uptermd/authorized_keys` 只放宿主公钥，不放用户日常密钥 |
| 调试开关 | 生产不开 `--debug` |
| journald | 保留量封顶 `200M` |
| 资源上限 | `MemoryMax 1G`、`CPUQuota 150%`、`TasksMax 512` |

### 3.3 runner 端（action-upterm）

| 项目 | 设计要求 |
| --- | --- |
| action 来源 | `owenthereal/action-upterm`，固定到 commit SHA，不用浮动 tag |
| 反连地址 | `upterm-server` 取 `ssh://relay.wuge.fun:22` |
| 用户限定 | `limit-access-to-users: itwuge` |
| 无人接入超时 | `wait-timeout-minutes: 10` |
| 客户端版本 | `upterm-version` 固定版本号，不取 latest |
| 主机指纹校验 | `known-hosts` 取仓库变量 `UPTERM_RELAY_KNOWN_HOST` |
| 超时上限 | 单步 `timeout-minutes: 40`，作业级 `45` |
| 不开启项 | `limit-access-to-actor`、`full-access`、`allow-exec`、`allow-forwarding` 四项一律不开 |

### 3.4 触发入口

| 入口 | 设计要求 | 说明 |
| --- | --- | --- |
| `workflow_dispatch` | 布尔开关，默认 `false`，需显式打开才起会话 | 默认关闭，避免误触 |
| `repository_dispatch` | 按关键词触发 | **风险**：由外部仓库或 bot 发起时 `github.actor` 可能不等于本人，`limit-access-to-users: itwuge` 的公钥限定可能失效；该入口须在实现时加来源校验，校验方式本身列入待实测/待定 |

### 3.5 凭据模型

| 类别 | 允许 | 禁止 |
| --- | --- | --- |
| 日志与页面可出现的字段 | 中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间 | 私钥、口令、一次性 token、GitHub token；不留中转机 |
| 会话标识 | 可出现在日志：本身不是凭据 | 不得把会话标识当作唯一认证手段 |
| 服务身份密钥 | host key、TLS key、CA key 允许存在，但须登记、`0600`、可轮换 | 不得下发到 runner 侧、不得进仓库 |
| 掩码底线 | 路由行原样可读 | 字段被掩码成 `***` 即判据一失败（见需求条目判据一） |

### 3.6 宿主注册密钥两条路

| 路径 | 条件 | 做法 | 处置 |
| --- | --- | --- | --- |
| 路径 A（优先） | uptermd 的 `authorized-keys` 支持 `cert-authority` | 离线 CA 每次签发 10 分钟证书，用完即废 | 无需长期白名单 |
| 路径 B（回退） | 不支持 `cert-authority` | 稳定密钥入 Secret + 服务端白名单 + 季度轮换 | **「宿主凭据非一次性」记为已知残余风险**，须在安全审查中登记 |

两条路何者可用取决于 uptermd 实际参数行为，列入必须实测清单第 1 项；实测前不假定路径 A 成立。

候选两条：WebAuthn；runner 反向 WebSocket + OIDC 换准入。两条均**未验证**，本方案只登记为待评估，不写接口、不写选型结论，待一期实测数据齐全后由用户决定是否立项，届时再评是否补 P07。

## 五、明确排除

以下做法一律不做：

- tmate 式连接串（tmate 已不可用，且其地址形态即排除对象）
- upterm 默认的不限定公钥模式
- `sshx`
- 网页 URL 带一次性 token
- `ttyd` 口令
- OAuth `client_secret` 落中转机

| 8 | 22 端口冲突处理 | 分别验证「系统 OpenSSH 迁 127.0.0.1:22022」与「仅白名单来源」两种做法 | 二者之一可行且不影响宿主自身 SSH 运维；给出所选做法的证据 | O01 | 未实测 |
