### 3.2 双入口共享同一会话路由

| 项目 | 填写内容 |
|---|---|
| 通道数 | 两条并行入口：SSH 通道（v2 既有，结论不变）与网页通道（v3 新增） |
| 共享对象 | 同一会话的同一路由键：`session_id` 为唯一键；SSH 通道由 `uptermd` 维护 `session_id → runner SSH 连接`，网页通道由桥接进程维护 `session_id → runner 反连 WS`；两个入口进入的是**同一个终端进程** |
| 路由建立 | runner 主动建立两条反连：SSH 反连注册到 `uptermd`，网页反连 WS 注册到桥接进程；两条通道使用同一 `session_id`。中继只记录映射，不判定谁有权进入 |
| 路由回收 | 会话结束或中继重启，映射删除；不写盘、不归档 |
| `[意图]` 并发进入 | 两个入口同时进入同一会话属允许行为，表现为两个终端视图共享一个终端进程；该行为对 TUI 的使用影响 `[待真机确认]`，实测前不承诺可用 |

### 3.3 中继职责边界

| 做什么 | 不做什么 |
|---|---|
| 接受 runner 的反向连接并登记 `session_id → 连接` 的内存映射（SSH 由 `uptermd`，网页由桥接进程） | 不终结身份认证：不校验访客公钥、不验 WebAuthn 断言、不验客户端证书 |
| 接受浏览器到 `/ws/<session_id>` 的 WS 连接，按 `session_id` 找到对应 runner 的网页反连 WS | 不做访问判定：不维护访客白名单，不判断「谁可以进」 |
| 接受 runner 到 `/runner/<session_id>` 的网页反连 WS，与浏览器 WS 配对 | 不把 `uptermd` 的 SSH-over-WS 当作自定义帧通道；两条通道协议不同，互不复用 |
| 由 `certbot-nginx` 在 443 终止 TLS，再把 `/ws/` 与 `/runner/` 转到桥接回环端口 | 不解析应用帧内容，不识别协议语义，不渲染终端；桥接不读帧负载做日志 |
| 双向转发字节流（SSH 协议字节、WS 帧负载），不做应用层解析 | 不落盘会话状态：不写会话文件、不写审计账本、不写回放数据 |
| 终止传输层 TLS（`wss://`），仅做加密与证书出示 | 不存任何用户凭据：无私钥、无口令、无一次性 token、无长期 bearer；仅可存公钥/公钥指纹用于路由绑定 |
| 记录连接元数据（地址、端口、`session_id`、指纹、时间）到系统日志 | 不限流、不做审计结论：限流与连接数控制下沉到 `nftables` 与 systemd，审计由系统层与 runner 侧承担 |
| 进程重启即清空全部映射 | 不保证重启期间会话连续：重启即断开，属预期行为 |

失去中继侧审计后的补偿与残余风险：

| 项 | 补偿手段 | 残余风险（照实记录） |
|---|---|---|

### 3.6 网页通道与公钥型认证

| 项目 | 填写内容 |
|---|---|
| 前端 | P07 主责，`web/` 下 TypeScript 编写的 xterm 类终端页；静态托管候选为 GitHub Pages（对外发布，需四类升级第 2 类放行）；前端只做终端渲染与本地签名，不含业务判定 |
| 连接 | 浏览器连 `wss://wuge.fun/ws/<session_id>`，由 `certbot-nginx` 终止 TLS 后转到桥接回环端口；runner 主动连 `wss://wuge.fun/runner/<session_id>`；桥接按同一 `session_id` 配对两条 WS，双向转发自定义帧。WS 路径只承载 `session_id`，**不承载任何凭据**；不复用 `uptermd` 的 SSH-over-WS 端点（协议不匹配） |

### 3.7 日志字段与「不得掩码」「四类载体零凭据」的关系

| 项目 | 填写内容 |
|---|---|
| 字段白名单（9 项常驻） | 中转地址、端口、会话标识、SSH 用户名、公钥指纹、到期时间、网页地址、公钥凭据标识、**当前路径**（`path_mode`，取值 `direct` 或 `relay`）；`pubkey_credential_id` 允许为 `unset`（设备完成 WebAuthn 注册前无值，视为已给出且合法，不属缺失） |
| 条件字段（直连面） | `direct_endpoint`：`path_mode=direct` 时必填，格式 `<100.x>:<端口>`，只填 tailnet 地址，不得填公网地址；`path_verified`：`path_mode=direct` 且发生首连后出现，取值 `direct`（真直连）/`derp`（Tailscale DERP）/`unknown`（未判定）；`path_mode=relay` 时二者不得出现；二者均属路由信息，不属凭据 |
| `ssh_user` 的构成 | upterm v0.41.1 **没有 ticket 概念**。`path_mode=relay` 时登录名形如 `<session_id>:<base64(节点地址)>`，冒号后是路由节点编码，属路由信息、不是凭据；`ssh_user` 必须原样输出**含冒号的完整登录名**，不得截断、改写或掩码。该路由编码不能用于换取登录：没有对应会话路由即不可达。`path_mode=direct` 时 `ssh_user` 为专用非 root 用户（如 `runner`，无冒号），不使用上述登录名 |
| 与「不得掩码」的关系 | 9 项常驻字段与 `direct_endpoint`、`path_verified` 两个条件字段均属可公开展示的元数据，**任一字段被掩码成 `***` 即判据一、判据五或判据七失败**；新增的网页地址、公钥凭据标识与当前路径同样不得掩码。掩码规则不得把整行路由信息一并抹掉 |
| 与「四类载体零凭据」的关系 | 私钥、口令、一次性 token、GitHub token 一律不得出现在日志、制品、构建摘要、仓库；网页地址本身不含凭据，若地址中出现任何凭据参数即判违规；公钥与公钥指纹属允许展示项，不构成凭据；mTLS 私钥若将来引入，只允许存在于设备，不得进入四类载体；Tailscale 临时 auth key 与节点私钥同属凭据，不得进入四类载体；`direct_endpoint`、`path_verified` 属路由信息，允许出现 |
| 交叉约束 | 判据五（网页入口）与判据六（中继无状态）不能以牺牲判据一（字段可读）为代价；若脱敏规则与字段可读冲突，以字段可读优先，凭据类内容一律在设计阶段就不产生 |

### 3.9 连接建立策略：Tailscale 直连优先，中继兜底

| 项目 | 填写内容 |
|---|---|
| 策略 | 会话建立先尝试 Tailscale 覆盖网络直连；auth key 缺失、加入失败、未取得 tailnet 地址或 sshd 绑定失败时，立即回落中继转发。`session_id` 在三个阶段不变，用户无需重新获取连接信息 |
| 直连面建立 | runner 用调用方仓库 Secret 中的临时 auth key 执行 `tailscale up`，取得 `100.64.0.0/10` 内地址；在该地址上起仅绑定该地址的 sshd。`[待真机确认]` |
| 超时 | `tailscale up` 整体超时上限候选 30 秒，**具体值待实测确定**；超时即判失败，不反复重试 |
| 判失败条件 | 任一条成立即判失败：① `TS_AUTHKEY` 缺失；② `tailscale up` 超时或返回非零；③ 未取得 tailnet IPv4；④ sshd 未能仅绑定该地址；⑤ auth key 过期或被 revoke |
| 回落动作 | 立即切中继转发，不重建 `session_id`、不重置会话；`path_mode=relay`，固定提示「直连未建立，已切换到中继转发」 |
| 判成功的留痕 | 日志记录 `path_mode=direct` 与 `direct_endpoint=<100.x>:<端口>`；首连后记录 `path_verified`；不记录任何密钥材料 |
| 用户可见提示 | 固定四条，只描述路径状态、不含任何凭据：「直连已建立」「直连未建立，数据经 Tailscale DERP 中继转发」「直连待验证，尚未确认是否经过 DERP」「直连未建立，已切换到中继转发」。允许出现地址、端口、`session_id`、`path_mode`、`path_verified` |
| 限制（必须写成条件成立，不得写成已具备能力） | GitHub **托管** runner 无入站端口；Tailscale 能尝试打洞，但成功率 `[待真机确认]`；对称 NAT 下会退到 DERP，数据经第三方，**不得声称纯 P2P**；`path_mode=direct` 只表示 tailnet 端点已发布，是否真直连以 `path_verified` 为准，**本期不作为纯 P2P 能力承诺** |
| 网页通道 | 一期网页通道固定走中继桥接，不实现浏览器打洞；直连面只承载 SSH，判据五不变 |
| 中继的角色 | 直连不可用时兜底；直连成功时中继不参与数据面，只保留 `uptermd` 的 SSH 登记与到期管理 |

| 项目 | 真直连（`path_mode=direct` + `path_verified=direct`） | DERP（`path_mode=direct` + `path_verified=derp`） | 中继（`path_mode=relay`） | 如何保证判据一致可判定 |
|---|---|---|---|---|
| 字段 | 9 项常驻 + `direct_endpoint` + `path_verified=direct` | 9 项常驻 + `direct_endpoint` + `path_verified=derp` | 9 项常驻；不出现 `direct_endpoint`/`path_verified` | 9 项常驻不随路径变化；`relay_host`/`port` 始终指中继入口，用于回落；差异只在条件字段 |

| 判据七（连接路径与回落） | 提示「直连已建立」 | 提示「直连未建立，数据经 Tailscale DERP 中继转发」 | 提示「直连未建立，已切换到中继转发」 | 三种形态各有通过分支；托管 runner 通常落在 DERP 或中继，真直连须实测并写明环境 |
| 不得出现 | 任何凭据；把 DERP 写成「直连已建立」 | 任何凭据；声称纯 P2P | 任何凭据；任何落盘会话 | 同一红线 |

### 3.10 直连路径细化（Tailscale）

| 项目 | 填写内容 |
|---|---|
| 两条数据面 | 中继面：用户 SSH 到中继 `22`，`uptermd` 转发到 runner 反向连接，runner 侧内嵌 sshd 终结认证；直连面：用户 SSH 到 `<100.x>:<端口>`，runner 侧 tailnet sshd 终结认证，中继不在路径上。两面的 sshd 均验访客公钥，中继不验、不判 |

| 与判据的关系 | 判据一扩为「9 项常驻 + direct 时 `direct_endpoint` + 首连后 `path_verified`」；判据四补「auth key 与节点私钥不进四类载体」；判据五不变；判据七扩为三种形态与四条提示语。详见需求条目 v7 与 `.team/records/设计更正-直连路径-20261109.md` |

## 六、数据模型

| 实体 | 字段 | 类型 | 必填 | 约束（唯一、范围、默认值） | 迁移策略 |
|---|---|---|---|---|---|
| 本项目无持久化数据模型 | 不适用 | 不适用 | 不适用 | 不写数据库、不落文件；会话状态只在中继内存与 runner 进程中存在，中继重启即清空 | 不适用 |
| 中继内存映射（非持久化） | `session_id` | 字符串 | 是 | 唯一键；高熵不可猜；进程重启即消失 | 不适用 |
| 中继内存映射（非持久化） | `runner_conn` | 连接引用 | 是 | SSH 反连连接引用；仅进程内有效，不序列化 | 不适用 |
| 网页桥接内存映射（非持久化） | `session_id` / `runner_ws` / `browser_ws[]` / `created_at` | 字符串与连接引用 | 是 | 按 `session_id` 唯一；`runner_ws` 只允许一条，`browser_ws` 上限 2；仅进程内有效，重启即清空；不落盘 | 不适用 |
| 中继内存映射（非持久化） | `bound_fingerprint` | 字符串 | 否 | 公钥指纹，仅作标识，不作判定依据 | 不适用 |
| 日志字段（非持久化契约） | `relay_host` / `port` / `session_id` / `ssh_user` / `pubkey_fingerprint` / `expires_at` / `web_url` / `pubkey_credential_id` / `path_mode` | 字符串与整数 | 是 | 9 项常驻齐备且原样可读；`port` 范围 1–65535；`relay_host`/`port` 始终指中继入口，用于回落；`ssh_user` 形态随 `path_mode`（`relay` 为含冒号的完整登录名，`direct` 为专用非 root 用户），不得截断或掩码；`expires_at` 为 ISO 8601 带时区；`path_mode` 取值 `direct` 或 `relay`；`pubkey_credential_id` 可为 `unset` | 不适用 |
| 日志条件字段（非持久化契约） | `direct_endpoint` / `path_verified` | 字符串 | 否 | `direct_endpoint` 仅 `path_mode=direct` 出现，格式 `<100.x>:<端口>`，只填 tailnet 地址；`path_verified` 仅 `path_mode=direct` 且首连后出现，取值 `direct`/`derp`/`unknown`；二者均属路由信息，不落盘 | 不适用 |
| 直连面运行期信息（非持久化） | `tailnet_ip` / 临时 host key / auth key 句柄 | 字符串 | 否 | 仅 runner 进程内有效；作业结束即销毁；不写仓库、不进日志 | 不适用 |

## 七、技术栈与选型理由

| 类别 | 选型 | 理由 | 被否决方案与被否决理由 | 是否花钱或占用资源 |
|---|---|---|---|---|
| 语言（脚本） | Shell（P08） | runner 与 Ubuntu 20.04 自带，无额外运行时 | 否决 Python：需装运行时，增加依赖面；否决 Go：本期不自研中继 | 否 |
| 语言（前端） | TypeScript（P07） | xterm 类终端库以 TS/JS 生态为主，类型检查能约束 WS 消息形状 | 否决纯 JS：无类型约束；否决 Rust/WASM 前端：构建链过重 | 否 |
| 语言（网页桥接） | Python 3.8 + asyncio + `websockets`（P04） | Ubuntu 20.04 自带 Python；异步字节转发轻量；P04 已在编制 | 否决 Node：需另装运行时；否决 Go：需补 P05 且本期不自研中继；否决纯 nginx：无法按 `session_id` 配对双向 WS | 否 |
| 前端库 | xterm.js 类终端库（MIT 候选） | 浏览器内终端事实标准，键盘与转义序列支持成熟 | 否决自写终端渲染：工作量大且易错；否决 iframe 嵌入现成终端服务：引入第三方托管 | 否 |
| 工作流平台 | GitHub Actions（`ubuntu-latest`） | 需求方已有仓库在该平台，runner 即目标编译环境 | 否决 GitLab CI：需另建仓库与 runner | 是（Actions 分钟数） |
| 反连客户端 | `owenthereal/action-upterm`，固定 commit SHA | 现成反连步骤，参数可控 | 否决 `sshx`：托管第三方；否决自写反连：需自管重连与指纹 | 否 |
| 中转进程 | `uptermd` 官方二进制，仅作转发、准入能力关闭 | 与客户端同源，协议一致；免自研 | 否决自建 SSH 跳板：需自管路由回收；否决通用反代如 `nginx stream`：不能按动态 `session_id` 路由 | 否 |
| 中转形态 | 无状态字节转发：SSH 由 `uptermd`、网页由桥接进程，各自内存映射，重启即清 | 缩小中转被攻破后的价值：无凭据、无会话、无审计账本可窃 | 否决有状态中继（原 v2 思路）：需落盘会话、承担审计与限流，与用户新增硬要求冲突 | 否 |
| 访客认证（SSH） | runner 内嵌 sshd 验访客公钥 | 认证点与终端同处，中继彻底退出认证链 | 否决中继 `authorized_keys` 白名单：即中继做判定，与降级冲突 | 否 |
| 访客认证（网页） | WebAuthn 应用层挑战，runner 侧验签 | 判定留在 runner 侧；私钥不出设备 | 否决 mTLS 由中继验证：中继需持 CA 并判定，冲突；否决口令：可爆破 | 否 |
| 直连覆盖网络 | Tailscale（临时 auth key + tailnet sshd） | 能穿 NAT 打洞；控制面托管、客户端成熟；auth key 支持 ephemeral、tag 与过期；SSH 客户端无需改造 | 否决 ZeroTier：生产机虽已运行，但需另维一套网络与身份，与 Tailscale 能力重叠；否决 ngrok/Cloudflare Tunnel：隧道终结在中转侧、等于第三方面向公网暴露；否决裸 WireGuard：自管协调与 NAT 穿透，运维成本高；否决 Tailscale SSH：引入第二条认证路径 | **是，按四类升级第 2 类**（DERP 情况数据经第三方）；**第 1 类**（节点与带宽占用） |
| 端口与 WS | 22 转发 SSH、443 由 nginx 转发 `/ws/` 与 `/runner/` 到桥接 `8081`（仅回环或 docker 网桥）；系统 OpenSSH 迁 `127.0.0.1:22022` 或仅白名单来源 | 用户默认端口连入，降低使用成本；桥接不暴露公网 | 否决 all-in-one 高端口：使用成本高；否决直接暴露桥接端口：增加暴露面 | 否 |
| 限流与防护 | `nftables` + systemd + 内核参数 | 中继不做限流，安全控制下沉系统层 | 否决中继续做限流：与无状态定位冲突 | 否 |
| 静态托管 | GitHub Pages（候选） | 前端为纯静态文件，免费且与仓库同源 | 否决中继托管静态页：违反「只转发」；否决第三方对象存储：新增账号与费用 | **是，需按四类升级第 2 类放行**（对外发布） |
| 部署宿主 | 阿里云成都 ECS（资源基线第一条） | 既有机器，延迟与带宽满足交互式 TUI | 否决新购：无必要支出 | **是，需按四类升级第 1 类** |

## 九、风险与回滚

| 序号 | 风险项 | 触发条件 | 影响面 | 回滚步骤 | 回滚判据 | 责任人（岗位编号） |
|---|---|---|---|---|---|---|
| 1 | 端口冲突致宿主 SSH 失联 | uptermd 占 22 且系统 OpenSSH 未迁移 | 宿主不可运维 | 云控制台 VNC 登入，停 uptermd，恢复 sshd 到 22 | `ss -ltnp` 显示 22 由 sshd 监听且可登录 | O01 |
| 2 | 中继重启中断进行中会话 | 服务崩溃、部署重启、资源打满被重启 | 两个入口同时断开，作业内 TUI 操作丢失 | 不恢复会话，等待下一次显式触发重建 | 重启后映射为空、原信息重连被拒 | O01 |
| 3 | 路由抢占（降级直接代价） | `session_id` 泄漏后被他人抢先注册同键 | 真实用户无法进入，属可用性问题；但**真实身份仍由 runner 侧验证，不构成认证绕过** | 重新触发生成新 `session_id`；必要时轮换反连注册标识 | 新会话可正常注册与进入 | O01、S01 |
| 4 | 失去中继侧审计导致事后无法复盘 | 安全事件发生 | 无身份级证据链，只有系统层连接元数据 | 依赖 runner 作业日志（若仍存在）与系统层计数 | 能给出时间、源地址、`session_id` 三元事实 | S01 |
| 5 | 凭据泄漏到日志或仓库 | 参数误写、字段实现不当 | 会话可被他人接管 | 立即轮换 host key、TLS key 与反连注册标识，刷新仓库变量 | 旧指纹与旧密钥全部失效，日志无凭据 | S01、O01 |
| 6 | 资源打满 | 并发会话或大文件传输 | 3 Mbps 带宽与 2 GiB 内存不足 | 依 `MemoryMax` 兜底；必要时停会话 | 资源回到配额内，服务自恢复 | O01 |
| 7 | `uptermd` 无法关闭准入能力 | 实测发现其转发必须带 `authorized_keys` 校验 | 「中继不做判定」无法成立 | 改通用 WS/TCP 中继（需重新评估语言负责人），或退回 v2 有状态形态并经用户拍板 | 中继日志中不再出现准入判定记录 | M03、O01 |
| 8 | WebAuthn 在 runner 侧验签不可行 | 无可用验签工具链或 RP ID 无法绑定 | 网页通道认证无法按设计完成 | 退回 SSH 单入口，网页通道顺延 | 认证路径有可复现实现 | M03、P08 |
| 9 | 直连误判或回落不彻底 | 判定条件过宽把不可用直连判成功；或回落时重建会话、更换 `session_id` | 用户按 `direct` 提示操作却连不上；或回落导致会话中断、需重新取连接信息 | 收紧判失败条件并提高 `tailscale up` 超时；回落流程改为「保留原 `session_id`、只切换承载路径」；无法稳定则关闭直连、固定 `path_mode=relay` | 在托管 runner 上稳定给出 `path_mode=relay` 且无需重新获取连接信息；关闭直连后行为与 v2 一致 | P08、O01 |
| 10 | 网页桥接进程成为单点或资源超限 | 桥接崩溃、内存/连接数打满、2 vCPU 争用 | 网页入口断开；SSH 入口不受影响 | systemd 自动重启；`MemoryMax=128M`、`CPUQuota=50%`、`TasksMax=64` 兜底；必要时停网页入口保 SSH | 桥接重启后配对为空、无文件；SSH 判据一至四仍通过 | P04、O01 |
| 11 | 网页反连注册被抢占 | 知道 `session_id` 的第三方先连 `/runner/<session_id>` | 真实 runner 被 `ROUTE_CONFLICT` 拒绝，网页入口不可用；属可用性问题，不构成认证绕过 | 使用 256 位随机 `session_id`；重触发换新标识；桥接只接受首个 runner 注册 | 新 `session_id` 可正常注册；旧标识无路由 | P04、O01、S01 |
| 12 | nginx WS 超时或缓冲导致断流 | `proxy_read_timeout` 过短、开启缓冲、Upgrade 头缺失 | 终端长时间无输入后被断开或输出延迟 | 关闭 `proxy_buffering`、显式设置 Upgrade/Connection、超时不低于会话上限；真机压测 | 连续 30 分钟无输入仍保持连接；输出无异常延迟 | O01 |
| 13 | DERP 被误标为直连 | 未读 `tailscale status`，仅凭 `tailscale up` 成功即输出「直连已建立」 | 用户以为纯 P2P，实际数据经第三方 | 必须首连后写 `path_verified`；`path_verified=derp` 固定提示「数据经 Tailscale DERP 中继转发」；不得出现「纯 P2P」表述 | 提示与 `path_verified` 一致；日志无「纯 P2P」断言 | P08、T01 |
| 14 | 临时 auth key 泄露或过期 | Secret 外泄、到期未轮换 | 他人可加入 tailnet，或 session 无法直连 | 管理台 revoke key → 删 `tag:actssh-runner` 节点 → 轮换 Secret → 查审计与日志 → 重跑验证；过期则回落 `relay` | 旧 key 失效、tailnet 无残留节点、`path_mode=relay` 可用 | G01、O01、S01 |
| 15 | tailnet sshd 绑定过宽或口令未禁 | 配置遗漏、沿用系统 sshd 默认值 | 公网或 tailnet 内非授权节点可尝试登录 | 仅绑 `<100.x>`；`sshd -T` 核对口令/root/转发项；`nftables` 只放 `tailscale0`；作业结束杀进程并 `tailscale down` | `ss -lntp` 只见 `<100.x>:<端口>`；`sshd -T` 相关项全为 `no` | P08、O01、S01 |
| 16 | 打洞成功率不稳定或用户设备不在 tailnet | 对称 NAT、企业网络封 UDP、用户未加入 tailnet | 直连入口不可达，体验回落到中继 | 日志同时保留中继入口；`path_mode`/`path_verified` 如实标注；不承诺纯 P2P | 用户可用中继完成会话；`path_verified` 与提示一致 | P08、T01 |

## 十、通过判据

| 序号 | 判据 | 合格标准 | 不合格处理 |
|---|---|---|---|
| 1 | 每个模块有主责岗 | 模块清单每一行主责岗位为具体编号且唯一 | 退回 M03 重写，不得派单 |
| 2 | 每个接口有签名 | 内部接口与对外接口每行都有完整签名或路径与字段 | 退回 M03 重写，不得派单 |
| 3 | 每个里程碑有可验收产物 | 批次表每行都有路径级产物、验收人与判据 | 退回 M03 重写，不得派单 |
| 4 | 技术选型有理由与被否决方案 | 技术栈每行都有理由与被否决方案，花钱项已标升级类别 | 退回 M03 重写，不得派单 |
| 5 | 设计意图与待确认项分开标注 | 全文结论均带 `[意图]` 或 `[待真机确认]`，无「已实现」断言 | 退回 M03 重写，不得派单 |
