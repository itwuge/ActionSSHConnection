# 07 TypeScript 细则

## 1. 文件名头要求

- 每个 `.ts` / `.tsx` 文件首部用 `/** */` JSDoc 块, 逐行写八栏。
- 文件头必须位于全部 `import` 之前; 中间不得插入其他注释。
- 八栏栏目名与顺序同总则, 单行形式 `* 文件: name.ts`。
- 禁止在文件头写 `@author`、`@date`、变更记录。
- 一个文件一个主要导出概念; 文件用途栏写不下时说明职责超载, 应拆分。

## 2. 依赖引入区要求

- 分三组: 运行时依赖 / 类型依赖 / 项目内模块, 组间空一行; 每行行尾 `//` 注明来源与用途。
- 纯类型必须用 `import type`, 不得混入运行时依赖。
- 禁止未使用引入; 禁止 `require`; 禁止 `import * as` 整包引入, 确需命名空间时注明原因。
- 路径别名必须在构建配置中登记, 并在引入处注明实际解析路径。
- 副作用引入(样式、全局注册)必须注明副作用内容。

## 3. 类型与函数注释要求

- 所有导出类型、接口、函数、类、常量必须有 JSDoc: `@param` / `@returns` / `@throws`。
- `@param` 除类型外必须写约束: 可空、取值范围、单位、格式; `@returns` 写失败时的返回取值; `@throws` 写触发条件与错误类型。
- 含多个公开方法的类在类注释中写「方法一览」, 形式为每行 `*   pick(name, response, default) -> Optional<Any>: 一句话用途`; 仅作速查, 参数与异常说明写在方法自身的 JSDoc 里。
- 必须写「为什么」: 为何用联合类型而不是枚举、为何返回结果对象而不是抛出异常、为何该字段可空。
- 约束: 禁止用 `any` 兜底。类型不明确时必须补类型定义、加运行时校验, 或写 `unknown` 并显式收窄; 禁止 `as unknown as` 强转绕过类型检查。违反即不合格。
- `// @ts-ignore` / `// @ts-expect-error` 必须写明原因与修复计划; 无原因者不合格。
- 禁止用注释代替类型: 类型信息必须写在类型系统中, 不写在注释文字里。

## 4. 行尾注释判据

- 只写原因不写翻译; 判据同总则。
- 本语言必写情形:
  - 可选链、空值合并的兜底取值理由。
  - 非空断言 `!` 的确信依据; 无依据必须改代码。
  - 异步状态机切换的顺序理由。
  - 超时、重试、轮询间隔常量的来源。
  - `useEffect` 依赖数组的取舍与刻意遗漏的依赖。
- 免写情形: 显然的赋值、纯转发、简单的 JSX 结构。
- 裁定结果按总则写入本节, 以案例沉淀。

## 5. 分区标记

- 形式: `// =========** 名称 =========**`。
- 标记下一行必须是该分区首行的 JSDoc 或一行职责说明; 标记本身不写职责说明。
- 分区顺序: 常量 -> 类型 -> 组件或类 -> 函数 -> 导出。
- 单组件文件同样必须写分区标记。

## 6. 标点与空格

- 注释内标点一律半角; 中文与英文或数字之间留一个空格。
- JSDoc 标签后紧跟一个空格; 标签名全小写。
- 全角标点只允许出现在面向用户的字符串字面量内; 注释中禁用书名号与直角引号, 改用半角引号。

## 7. 违规范例(一条)

```ts
// 不合格示例: 用 any 兜底, JSDoc 缺 @returns
export function parse(input: any): any { return input; }
```

问题:

- 参数与返回值用 `any` 兜底, 类型信息丢失。
- 缺 `@param` / `@returns` / `@throws`。
- 未说明解析失败时的返回取值。

## 8. 交付前自检清单

- [ ] 文件头 JSDoc 八栏齐全, 位于全部 `import` 之前。
- [ ] `import` 分组正确, 纯类型用 `import type`, 无未使用引入。
- [ ] 导出成员全部有 `@param` / `@returns` / `@throws`。
- [ ] 含多个公开方法的类写了「方法一览」。
- [ ] 全仓无 `any` 兜底与 `as unknown as` 绕过。
- [ ] `@ts-ignore` 类注释均写明原因与修复计划。
- [ ] 行尾注释只写原因, 分区标记统一。
- [ ] `tsc --noEmit` 与 lint 通过。
