## 五、接口契约

### 5.1 内部接口

> 本项目形态为脚本自动化型，既非 Web 也非桌面，按 `14_交互契约` 第 3 节命令函数约定与第 5 节 Shell 行执行：入口函数不加 `_` 前缀，内部函数加 `_` 前缀；返回结构固定五字段；Shell 契约三项（入参顺序与含义、退出码、stdout 格式）逐函数写明。

| 序号 | 接口或函数名 | 提供方 → 调用方（岗位编号） | 完整签名 | 返回结构 | 错误码 | 对应契约版本 |
|---|---|---|---|---|---|---|
| 1 | `deploy_relay` | P08 → O01 | `deploy_relay <host> <port> <expected_fingerprint>`；位置参数依次为宿主域名、SSH 端口、预期主机指纹；退出码 0 成功、1 取不到（连不上或指纹不符）、2 出错（安装或启动失败）；stdout 为单行 JSON | `{ok, message, error_code, data, confirm}`，`data` 含 `service_state`、`unit_name` | `RELAY_FINGERPRINT_MISMATCH`、`RELAY_START_FAILED` | 契约 v1 |
| 2 | `check_relay_health` | P08 → O01、T01 | `check_relay_health <host> <port>`；退出码 0 健康、1 取不到、2 出错；stdout 单行 JSON | 同五字段结构，`data` 含 `listen_state`、`metrics_scope`、`journal_cap` | 无（失败只给文案） | 契约 v1 |
| 3 | `rotate_session_key` | P08 → O01 | `rotate_session_key <key_id> <confirm_token>`；退出码 0 轮换完成、1 取不到（`key_id` 不存在）、2 出错；stdout 单行 JSON | 五字段结构；未带令牌时 `ok` 为假且 `confirm` 非空，含 `prompt` 与 `token` | `KEY_NOT_FOUND` | 契约 v1 |
| 4 | `open_session` | G01 → 终端 | `open_session <relay_host> <port> <ssh_user>`；退出码 0 会话结束且作业成功、1 认证被拒、2 会话步骤出错；stdout 不承载会话内容，仅承载六项字段行 | 五字段结构，`data` 含六项：`relay_host`、`port`、`session_id`、`ssh_user`、`pubkey_fingerprint`、`expires_at` | `AUTH_DENIED` | 契约 v1 |

### 5.2 对外 API

> 本项目无对外 HTTP API。对外调用面为 GitHub 工作流事件入口，按事件方式登记如下；不放接口版本号，改用工作流文件路径定位。

| 序号 | 方法 | 路径 | 请求字段 | 响应包络 | 错误码 | 幂等要求 |
|---|---|---|---|---|---|---|
| 1 | `workflow_dispatch` | `.github/workflows/session.yml` | `start_session`：布尔，默认 `false` | 无 HTTP 响应；结果为 Actions 运行结论与日志 | 无 | 同一 `run_id` 只建一次会话；重复触发生成新的 `run_id` |
| 2 | `repository_dispatch` | `.github/workflows/session.yml` | `event_type` 固定 `start-session`；`client_payload.keyword` 为字符串 | 同上 | 无 | 同一 `delivery_id` 去重，重复投递只执行一次 |

> `repository_dispatch` 的已知风险：发起方为外部仓库或 bot 时 `github.actor` 可能不等于本人，`limit-access-to-users: itwuge` 的公钥限定可能失效。该入口在本设计书中**只登记形状，不视为已定方案**；启用前必须先解决来源校验，校验方式列入必须实测清单并单独出结论。

## 七、技术栈与选型理由

| 类别（语言/框架/库/存储/构建/部署） | 选型 | 理由 | 被否决方案与被否决理由 | 是否花钱或占用资源 |
|---|---|---|---|---|
| 语言（脚本与工作流） | Shell（P08 负责） | 工作流内联步骤与部署脚本的全部逻辑可由 Shell 完成，runner 与 Ubuntu 20.04 均自带，无额外运行时 | 否决 Python：需在 runner 与宿主装运行时，增加依赖面；否决 Go：本期不自研服务端代码 | 否 |
| 工作流平台 | GitHub Actions（`ubuntu-latest`） | 需求方已有仓库在该平台，runner 环境即目标编译环境 | 否决 GitLab CI：需要另建仓库与 runner；否决本地容器：无法复现 CI 环境 | 是，占用 Actions 分钟数 |
| 反连客户端 | `owenthereal/action-upterm`，固定到 commit SHA | 提供 runner 侧反连与公钥限定的现成步骤，参数可控 | 否决 `sshx`：托管第三方；否决自写反连脚本：需自管重连、指纹与超时 | 否 |
| 中转服务端 | `uptermd` 官方二进制，固定版本，systemd 常驻 | 与客户端同源，协议一致；官方二进制免自研，不引入 Go 开发 | 否决自建 SSH 跳板：需自管会话多路复用与路由回收；否决 tmate 服务端：tmate 已不可用 | 否（开源免费） |
| 宿主系统 | Ubuntu 20.04（资源基线既有） | 与资源基线一致，systemd 与 OpenSSH 版本满足要求 | 否决重装其他发行版：属不可逆操作且无收益 | 否 |
| 监听与端口方案 | uptermd 监听 `0.0.0.0:22`；系统 OpenSSH 迁 `127.0.0.1:22022` 或仅白名单来源 | 需求方默认端口连入，减少使用成本；宿主自身 SSH 运维保留可控入口 | 否决 uptermd 改用高端口：用户每次要记端口，且不解决占用 22 的诉求 | 否 |
| 部署宿主 | 阿里云成都 ECS（资源基线第一条：2 vCPU / 2 GiB / 3 Mbps） | 资源基线既有机器，延迟与带宽满足交互式 TUI | 否决新购机器：无必要支出；否决家用宽带自建：无固定公网地址与备案域名 | 是，**需按四类升级处理·第 1 类**（花钱或占用资源） |

## 九、风险与回滚

| 序号 | 风险项 | 触发条件 | 影响面 | 回滚步骤 | 回滚判据 | 责任人（岗位编号） |
|---|---|---|---|---|---|---|
| 1 | 端口冲突致宿主 SSH 失联 | uptermd 占用 22 且系统 OpenSSH 未迁移 | 宿主不可运维，中转整体不可用 | 经云控制台 VNC 登入，停 uptermd，恢复 sshd 到 22 | `ss -ltnp` 显示 22 由 sshd 监听且可登录 | O01 |
| 2 | 会话残留（僵尸路由） | runner 强杀或断网 | 公网可连到已失效会话，暴露面延长 | 重启 uptermd 服务并核对路由表；必要时按进程强制清理 | 原信息重连被拒，无异常进程 | O01 |
| 3 | 凭据泄漏到日志或仓库 | 参数误写、掩码规则冲突 | 会话可被他人接管 | 立即轮换 host key、CA key 与宿主注册密钥，并刷新仓库变量 | 旧指纹与旧密钥全部失效，日志无凭据 | S01、O01 |
| 4 | 宿主凭据非一次性 | uptermd 不支持 `cert-authority`，回退稳定密钥方案 | 密钥泄露窗口等于轮换周期 | 按季度轮换并登记；如支持 `cert-authority` 则切回 10 分钟证书 | 轮换记录齐全且旧密钥失效 | O01 |
| 5 | 资源打满 | 会话并发或大文件传输 | 3 Mbps 带宽与 2 GiB 内存不足，服务被 OOM | 依 `MemoryMax` 上限由 systemd 兜底；必要时停会话并压缩传输量 | 内存与 CPU 回落到配额内，服务自动恢复 | O01 |
| 6 | 22 端口被云安全组或运营商限制 | 云侧策略变更 | 外部无法连入 | 改走白名单来源方案或申请放通 22 | 外部 SSH 可连且宿主 sshd 不受影响 | O01 |
