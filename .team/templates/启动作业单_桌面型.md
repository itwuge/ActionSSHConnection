# 桌面型项目启动作业单

> 本作业单是「项目启动包」在桌面客户端型项目里的执行版清单：照表复制、照表建目录、照表勾检，不再另行取舍。执行人 M01，记录人 M04，验收取证 T01。源路径一律相对项目启动包根目录，目标路径一律相对项目根目录。

## 一、适用条件

同时满足以下四条，才按本作业单开工：

1. 交付物是安装到用户本机的程序，有安装包或可执行文件，不是打开浏览器即用的网页。
2. 运行时有原生窗口（系统窗口、托盘、菜单或原生对话框），界面在操作系统桌面内绘制。
3. 需要与系统层交互：文件系统、注册表或系统配置、进程与服务、网络端口、设备或剪贴板等至少一项。
4. 需要安装、升级与回滚方案，产物由 G01 走 Release，由 O01 管分发与回滚。

不符合的按下述归类，不套用本作业单：

- 纯网页、只在浏览器内运行：属 Web 站点型，待补对应作业单。
- 无窗口、只由定时器或命令行触发：属脚本自动化型，待补对应作业单。
- 只交付文档、方案或评测，无代码与运行环境：属文档与方案型，待补对应作业单。
- 手机或平板上安装的原生应用，无桌面窗口与桌面系统层交互：不属本作业单范围。

## 二、目录搭建

按下表建立目录。目录名与文件名一律照写，不另起别名。

```text
项目根/
├─ 用法.md                      唯一入口，放根目录
└─ .team/
   ├─ hard-rules.md             硬约束副本，16 条原样，只读
   ├─ specs/                    规范副本与来源记录
   │  ├─ 00_总则.md
   │  ├─ 02_Rust.md
   │  ├─ 03_C.md
   │  ├─ 06_Dart.md
   │  ├─ 09_异常捕获.md
   │  ├─ 10_日志.md
   │  ├─ 11_Debug.md
   │  ├─ 12_团队规范.md
   │  ├─ 13_指挥规范.md
   │  ├─ 14_交互契约.md
   │  └─ 来源记录.md            版本、复制日期、作业单、生效范围
   ├─ roles/                    本项目启用的 13 份角色卡
   ├─ templates/                五份空白模板与模板使用说明
   └─ records/                  留档
      ├─ 会议纪要/
      ├─ 验收报告/
      └─ 自检/                  开工自检与收工自检记录
```

逐级用途与约束：

| 路径 | 用途 | 约束 |
| --- | --- | --- |
| 用法.md | 项目唯一入口，讲开工三步、编制、记忆、自检与接入 | 根目录只放这一份，不散放规范副本 |
| .team/hard-rules.md | 硬约束副本，红线、交付、报告、权限、推进共 16 条 | 只读，不增不删不改写；项目专属规则不进此文件 |
| .team/specs/ | 规范副本：总则、本项目语言细则、09 至 14 | 保留母版文件名；项目内改动须在文件头写明原因 |
| .team/specs/来源记录.md | 记复制日期、来源路径与母版版本、所依据作业单、生效范围四栏 | 分次补挂逐次记一笔，不重写整份记录 |
| .team/roles/ | 本项目启用的 13 份角色卡副本 | 只放启用岗位；不放 00_编制总览.md，不放 _角色卡模板.md |
| .team/templates/ | 五份空白模板与模板使用说明 | 空白模板不改写，填写时另存为正式文件 |
| .team/records/会议纪要/ | 需求评审、契约评审、验收评审、发布评审的纪要 | 会后当日出具，缺裁决人或结论视为未开 |
| .team/records/验收报告/ | 按「模板名-编号-年月日」命名，如 验收报告-需求-202611-001-20261108.md | 必须带证据链：操作步骤、截图或录屏路径、结论对应判据 |
| .team/records/自检/ | 开工自检-年月日.md、收工自检-年月日.md | 每轮各一份，缺项写明原因与补验计划 |

### 语言细则怎么挑

上表按桌面客户端型项目的默认栈（Rust 系统能力 + C ABI + Dart/Flutter 客户端）取细则。实际栈不同时，按下表替换语言细则行，并同步调整岗位与角色卡：

| 项目实际用的栈 | 带的语言细则 | 同步动作 |
| --- | --- | --- |
| Rust 系统能力（默认栈） | 规范\02_Rust.md | 启用 P01，带 05_P01_Rust专家.md |
| C 模块与 C ABI（默认栈） | 规范\03_C.md | 启用 P02，带 06_P02_C专家.md |
| Dart/Flutter 客户端（默认栈） | 规范\06_Dart.md | 启用 P06，带 10_P06_Dart专家.md |
| Qt/PySide6 桌面界面 | 规范\01_Python.md | 改由 P04 负责界面层，带 08_P04_Python专家.md；同时撤下 06_Dart 与 P06 |
| 原生 C++ 与 CMake | 规范\04_CPP.md | 启用 P03，带 07_P03_C++专家.md |
| Electron/WebView 前端 | 规范\07_TypeScript.md | 启用 P07、H01、W01，带 11_P07_TypeScript专家.md、21_H01_界面实现专家.md、22_W01_Web专家.md；HTML/CSS 无独立细则文件，按 00_总则与 07_TypeScript 执行 |

当前未带、以及为什么不带：

- 规范\01_Python.md：默认栈无 Python 侧工具与数据处理，P04 不启用；改用 Qt/PySide6 时补带。
- 规范\04_CPP.md：默认栈无 C++ 模块与 CMake 层，第三方库经 C ABI 接入，P03 不启用；引入原生 C++ 时补带。
- 规范\05_Go.md：无自建服务端与 CLI 并发需求，P05 不启用；增设服务端时补带。
- 规范\07_TypeScript.md：无 Web 前端与 Node 侧脚本，P07 不启用；改 Electron/WebView 时补带。
- 规范\08_Shell.md：脚本只有零散构建命令，由 P01、P02 与 O01 承担，P08 不启用；脚本成体系时补带。
- 资源基线.md：母版按具体机型与带宽写定，桌面客户端型项目不引用部署基线，留在母版；O01 排部署若需引用，按源文件原样补进 .team/specs/ 并记入来源记录。
- 模板\示例\ 目录全部内容：示例含具体项目内容与截图，复制进项目会被当成正式记录，一律不复制。
- 员工\00_编制总览.md、员工\_角色卡模板.md：编制真源与建卡模板，项目内只保留启用岗位的角色卡，这两份留在母版。

## 七、常见错误

1. 把 22 份角色卡全搬进 .team/roles/：项目里出现无人负责的岗位，边界互相踩，责任落不到人。只复制第四节启用的 13 份。
2. 漏带 12_团队规范.md 与 13_指挥规范.md：以「只是流程文档，与代码无关」为由不带，结果提交格式与转派无人认账。有代码、多人协作的项目两份都必带。
3. 把 模板\示例\ 连同五份空白模板一起复制：项目里混入带具体项目内容的示例文档与截图，后续被当成正式需求、纪要或验收记录引用。只复制五份空白模板与 00_使用说明.md。
4. 把 00_编制总览.md 与 _角色卡模板.md 当岗位卡复制进 .team/roles/：这两份是编制真源与建卡模板，不是岗位，进 roles/ 会与「只放启用岗位」冲突，并让 M01 误以为多出岗位。
5. 按「项目用 Rust」只带 02_Rust.md、不带 03_C.md：桌面型有 C ABI 层，漏带后导出面与内存归属无规则可依。语言细则按第三节「语言细则怎么挑」逐行配齐。
6. 把 规范 副本散放到项目根，只在 .team/ 放硬约束：根目录同名文件互相覆盖，引用断链。根目录只放 用法.md，其余进 .team/。
7. 用桌面绝对路径写引用：换机器或换目录即断链，来源记录也无法回查。一律写项目内相对路径。
