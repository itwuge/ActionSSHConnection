# 接入指南

本文说明如何把本仓库当作工具箱，在**别的项目**里开一个可 SSH / 网页接入的临时调试会话。
本仓库自身的 `.github/workflows/session.yml` 已经改成薄封装，与本文示例共用同一份实现。

---

## 1. 两种接入方式与选型理由

### 1.1 Composite Action（默认推荐）

```yaml
- uses: itwuge/ActionSSHConnection@v1
  with:
    ssh: true
```

- 实现在仓库根 `action.yml`，`runs.using: composite`；脚本在 `scripts/action/`。
- 它是调用方 job 里的一步，`runs-on` / `timeout-minutes` / `permissions` / 前后步骤都由调用方掌握。
- 升级只改 `@v1`（或锁定的 SHA），不用改 job 结构。
- 局限：Action 会阻塞到会话结束；会话进行中要读路由字段，需要 `route-artifact-name` 走制品。

**理由**：多数项目只缺"开会话"这一步，其余（构建、通知、并发控制）已有自己的流水线，步骤级嵌入侵入最小。

### 1.2 可复用工作流

```yaml
jobs:
  debug:
    permissions:
      contents: read
    uses: itwuge/ActionSSHConnection/.github/workflows/reusable-session.yml@v1
    with:
      ssh: true
```

- 实现在 `.github/workflows/reusable-session.yml`，`on: workflow_call`。
- 占据的是 **job 级** 位置，运行器、超时、清理全部由本仓库托管；输出用 `needs.<job>.outputs.*`。
- 局限：调用方不能在同一个 job 里插自己的步骤；inputs 的类型与默认值由本仓库定义。

**理由**：给"只想拿一个会话、不想维护 job 模板"的项目用；它内部会检出本仓库并调用**同一个** Composite Action，不存在两份实现。

## 2. 前置条件

| 项 | 要求 |
| --- | --- |
| 运行器 | `ubuntu-latest`（Linux）。Windows / macOS 未支持 |
| 内置命令 | `bash` `jq` `python3` `gh` `tmux` `ssh-keygen` `curl`（GitHub 托管 Ubuntu 镜像自带） |
| 权限 | workflow 或 job 至少 `permissions: contents: read` |
| 网络 | 出网可达 `github.com`（下载 upterm 客户端）、中继 `2222`（uptermd）、`443`（网页与 `wss` 桥接）；直连模式另需出网可达 `tailscale.com`、`controlplane.tailscale.com` 与 UDP `41641`/TCP `443`（DERP） |
| 自建中继 | uptermd 0.41.1 已运行；nginx 已提供 `/t/`、`/ws/`、`/runner/` 三个入口 |
| 直连（可选） | 一个 Tailscale tailnet、一个临时 auth key（ephemeral + `tag:actssh-runner`）、调用方设备已加入同一个 tailnet；runner 上的 Tailscale 与 sshd 由本 Action 自行安装，不依赖宿主预装 |

调用方仓库变量（非秘密路由信息）：

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `UPTERM_RELAY_KNOWN_HOST` | 是 | 中继主机公钥行，写成 `[host]:port ssh-ed25519 AAAA...` |
| `WEB_TERMINAL_BASE_URL` | 是 | 网页站点根地址，如 `https://wuge.fun`，不含 `/t/` |
| `WEB_BRIDGE_BASE_URL` | 是（网页通道） | runner 反连基地址，如 `wss://wuge.fun`，自动补 `/runner` |
| `WEBAUTHN_ALLOWED_CREDENTIALS` | 是（网页通道） | 单行 JSON 数组；`[]` 表示开放一次自举注册 |
| `WEBAUTHN_CREDENTIAL_ID` | 否 | 已注册的凭据标识；通过 `credential-id` 输入传入（Composite 里用 `credential-id: ${{ vars.WEBAUTHN_CREDENTIAL_ID }}`），留空即输出 `unset` 并走自举注册 |
| `UPTERM_DIRECT_MODE` | 否 | 本仓库自用入口的直连开关；只有 `none` / `tailscale` 两个合法值，默认 `none` |

调用方仓库 Secret（只给直连模式）：

| Secret | 必需 | 说明 |
| --- | --- | --- |
| `TS_AUTHKEY` | 直连时必需 | Tailscale 临时 auth key。用 `tailscale authkey --ephemeral --preauth --tags tag:actssh-runner` 生成；只从环境读取，不打印、不落盘、不进制品。缺失或过期时按设计回落中继，作业不失败 |

> SSH 通道只需要前三项里的前两项（`known-hosts` 与 `ssh-user`）；后三项仅网页通道使用。直连模式额外需要 `direct-mode: tailscale` 与 `tailscale-auth-key`。

`ssh: false`（默认）只做前置校验，不安装客户端、不反连中继、不启动网页桥接，路由字段输出 `none`。

## 3. 中继侧需要的东西与最小验证

### 3.1 地址与 known_hosts

- uptermd 地址：`ssh.wuge.fun:2222`（注意：不是宿主 sshd 的 22 端口）。
- `known_hosts` 行必须是方括号形式，端口写在方括号里：

```
[ssh.wuge.fun]:2222 ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIIP8Ue4hfxEXVelScsPdHN837quBEx/K6GCd+p6jrl34
```

自行采集并核对指纹：

```bash
ssh-keyscan -p 2222 ssh.wuge.fun
ssh-keygen -lf <(ssh-keyscan -p 2222 ssh.wuge.fun 2>/dev/null)
```

### 3.2 网页桥接端点

- 浏览器入口：`https://<站点>/t/<session_id>`
- 网页 WebSocket：`wss://<站点>/ws/<session_id>`（浏览器 → 中继）
- runner 反连：`wss://<站点>/runner/<session_id>`（runner → 中继）

nginx 需要把 `/ws/` 与 `/runner/` 都按 WebSocket Upgrade 转发（参考 `deploy/nginx/web-bridge-location.conf`）。

### 3.3 最小验证（部署后、接入前各做一次）

```bash
# 1) 页面可加载（返回 200/HTML，不是 404）
curl -sI https://wuge.fun/t/any-session | head -1

# 2) 两个 WebSocket 入口存在（未带 Upgrade 时应为 426）
curl -sI https://wuge.fun/ws/any-session | head -1
curl -sI https://wuge.fun/runner/any-session | head -1

# 3) 中继 uptermd 可达（预期出现 SSH banner 或 publickey 提示）
ssh -o StrictHostKeyChecking=no -p 2222 itwuge@ssh.wuge.fun true
```

三条都符合预期，再触发一次 `ssh: true` 的运行。

## 4. 直连路径（Tailscale，可选）

### 4.1 调用方需要准备什么

1. 一个 tailnet（Tailscale 管理台创建，免费档即可）。
2. 调用方设备加入同一个 tailnet 并登录；设备不在 tailnet 里时直连地址不可达。
3. 生成临时 auth key：

```bash
tailscale authkey --ephemeral --preauth --tags tag:actssh-runner
```

4. ACL 只放行调用方身份到 `tag:actssh-runner` 的 SSH 端口（端口与 `direct-ssh-port` 一致）：

```json
{
  "tagOwners": { "tag:actssh-runner": ["autogroup:admin"] },
  "acls": [
    { "action": "accept", "src": ["autogroup:admin"], "dst": ["tag:actssh-runner:2222"] }
  ]
}
```

5. 把 key 存为调用方仓库 Secret（如 `TS_AUTHKEY`），调用时传入：

```yaml
- uses: itwuge/ActionSSHConnection@v1
  with:
    ssh: true
    direct-mode: tailscale
    tailscale-auth-key: ${{ secrets.TS_AUTHKEY }}
    direct-ssh-port: "2222"
```

可复用工作流改用 `secrets` 映射：

```yaml
jobs:
  debug:
    permissions: { contents: read }
    uses: itwuge/ActionSSHConnection/.github/workflows/reusable-session.yml@v1
    with:
      ssh: true
      direct-mode: tailscale
      direct-ssh-port: "2222"
    secrets:
      tailscale-auth-key: ${{ secrets.TS_AUTHKEY }}
```

### 4.2 runner 侧做什么

| 步骤 | 做法 |
| --- | --- |
| 安装 | 缺失时用官方脚本安装 Tailscale 与 openssh-server（全新机器口径，不假设宿主已装） |
| 加入 | 临时 auth key 写 0600 文件后以 `file:` 读取，随即删除；`tailscale up --hostname=actssh-<run_id> --advertise-tags=tag:actssh-runner --ephemeral --ssh=false --accept-routes=false --accept-dns=false`，30 秒超时 |
| sshd | 只 `ListenAddress <100.x>`，端口取 `direct-ssh-port`（默认 2222）；每轮临时 host key；`authorized_keys` 复用从 GitHub 公钥接口拉取的清单，随作业销毁 |
| 防火墙 | nftables 前缀表只允许 `tailscale0` 到该端口；sshd 本身也只绑 tailnet 地址 |
| 输出 | `path_mode=direct`、`direct_endpoint=<100.x>:<端口>`，`path_verified` 初始 `unknown` |
| 收尾 | `tailscale down` + `logout`（ephemeral 节点随会话移除）、杀 sshd、删 host key/授权清单/临时状态、删 nft 表 |

**`kill -9` 或 runner 掉电的残留兜底**：`trap` 不会执行，但 sshd、tailscaled 与临时目录都随 runner 一起消失，不会留下可登入面。最坏情况下只是 tailnet 里短暂留下一个离线节点——auth key 用 `ephemeral` 时节点在会话结束后由 Tailscale 自动回收，且 key 本身建议有效期 ≤ 24 小时；必要时在管理台按 `tag:actssh-runner` 批量删除节点并 revoke key。

### 4.3 连接方法

日志里的 `direct_endpoint` 是 `<tailnet-ip>:<port>`，`ssh_user` 是直连登录名（专用非 root 用户，通常 `runner`，无冒号）：

```bash
ssh -o StrictHostKeyChecking=accept-new -p 2222 runner@100.x.y.z
```

每轮 host key 都是临时的，首次连接建议用 `accept-new`；认证仍只认 `ssh-user` 这个 GitHub 账号登记的公钥。

### 4.4 path_verified：必须区分真直连与 DERP

`path_mode=direct` 只说明 tailnet 路径可用，**不等于纯 P2P**。首次连接后脚本读取 `tailscale status --json`：peer 的 `Active` 为真且 `CurAddr` 非空 → `path_verified=direct`；只有 `Relay` → `derp`（数据经 Tailscale 的第三方 DERP 中继）；没有活动连接或状态不可读 → `unknown`。

| path_mode | direct_endpoint | path_verified | 数据面 | 固定提示语 |
| --- | --- | --- | --- | --- |
| direct | 必填 | direct | 两端直接（打洞成功） | 直连已建立 |
| direct | 必填 | derp | Tailscale DERP（第三方），不是纯 P2P | 直连未建立，数据经 Tailscale DERP 中继转发 |
| direct | 必填 | unknown | 尚未连接或无法判定 | 直连待验证，尚未确认是否经过 DERP |
| relay | 不出现 | 不出现 | 本项目中继 | 直连未建立，已切换到中继转发 |

`direct_endpoint` 与 `path_verified` 是条件路由字段，不新增 output：它们出现在相关步骤的日志与作业摘要里，`path_verified` 的变化也会追加到摘要。9 个 outputs 与 `fields` 制品仍是 9 行。

### 4.5 回落

以下任一情况回落 `path_mode=relay`，`session_id` 不变，作业不失败，用户继续用中继连接串：

1. 未传 `tailscale-auth-key`（Secret 缺失）；
2. `tailscale up` 30 秒内失败或超时（key 过期、无 tag 权限、网络不通）；
3. 未取得 `100.64.0.0/10` 地址；
4. sshd 校验、启动或监听失败；
5. 运行器没有免密 sudo，装不上 Tailscale 或 sshd。

回落时日志出现 `失败[阶段 ...]：…；直连不可用，按设计回落中继` 与 `::warning::`，并输出「直连未建立，已切换到中继转发」。中继连接方式不变。

## 5. 安全边界

1. **日志只出 9 个路由字段与直连条件字段**：9 项为 `session_id`、`ssh_user`、`relay_host`、`relay_port`、`web_url`、`pubkey_fingerprint`、`expires_at`、`pubkey_credential_id`、`path_mode`；直连时另有 `direct_endpoint` 与 `path_verified`（均为路由信息）。客户端原始 JSON、连接串、公钥内容、断言材料都不外显，原始文件解析后立即删除。**auth key 只从环境读入 0600 临时文件、以 `file:` 交给 tailscale 后立即删除，不打印、不进制品、不进构建摘要、不进提交。**
2. **闸门必须开启**：访客公钥只从 `ssh-user` 这个 GitHub 账号的公钥接口拉取；`repository_dispatch` 入口还会校验发起者与 `ssh-user` 一致。不要为图方便改成"接受任意公钥"。
3. **空清单自举的残余风险**：`allowed-credentials: "[]"` 时，**第一个**完成 WebAuthn 注册的人即获得该会话终端；同一会话只接受一次注册，会话结束即失效。生产环境应预置 `credential_id` + `public_key` 条目。
4. **凭据不落四类载体**：私钥不在仓库变量、不在日志、不在制品、不进入提交。本仓库只保存公开标识（公钥指纹、凭据标识、known_hosts 公钥）。
5. **会话生命周期**：存活期内同一 `session_id` 可反复进入（断开、`exit`、网页关标签页后重连都有效，不需要重新触发）。结束只有四种：显式 `upterm session stop actssh`、空闲超时、`session-minutes`、job 超时。`session-minutes` 决定 `expires-at` 与等待超时；空闲超时由 `idle-minutes`（默认 10 分钟，SSH 与网页合计）控制。会话结束后重连一律被拒。
6. **失败尝试上限**：网页通道单连接 3 次、全会话 10 次 / 10 分钟滑窗，超限只在窗口内拒绝新准入（不结束会话）。SSH 访客认证在中继侧完成，runner 日志只有 `Client joined`/`Client left`，看不到失败次数，需要限速请在中继 `uptermd` 或前置网关按来源 IP 做。

## 6. 已知限制与未验证项

照实标注，均**不是**已具备能力：

- **直连不是纯 P2P**：`path_mode=direct` 只表示 tailnet 路径可用；对称 NAT 下 Tailscale 会退到 DERP，数据经第三方转发。只有 `path_verified=direct` 才能说点对点，`path_verified=derp` 必须按「数据经 Tailscale DERP 中继转发」理解。
- **直连真机验证项（未取证前不承诺）**：托管 runner 打洞成功率、DERP 回落识别的稳定性、tailnet 内 SSH 端口可达性、auth key 过期行为、`tailscale up` 超时与失败清理、runner 出站 UDP 41641 / TCP 443、ACL 只到该 runner、临时 host key 与用户 `known_hosts` 的 `accept-new` 行为，均需在有真实 tailnet 凭据的环境中逐项取证。
- **直连面只承载 SSH**：网页终端仍走中继桥接，`direct_endpoint` 与网页 URL 无关。
- **upterm 版本白名单只有 `v0.41.1`**：`upterm-version` 传其他值会被拒绝（没有内置校验和）。
- **网页通道依赖中继侧桥接服务**：`/runner/` 反连与 `/ws/` 转发不可用时，SSH 仍可用，日志会按 `bridge-connect` / `bridge-register` / `bridge-admission` 报出阶段。
- **WebAuthn 真实域名验签未在浏览器完成**：本机测试环境无可用平台认证器，注册在 45 秒认证超时后失败；服务端请求与超时行为已取证，签名验签链路仍待有认证器的机器确认。
- **Windows / macOS 运行器不支持**：脚本依赖 bash、tmux 与 POSIX 工具链。
- **可复用工作流的 `action-upterm-ref`**：它决定检出哪个 ref 的本仓库代码，需与调用方锁定的 `@ref` 保持一致；两者不一致会拿到不同版本的脚本。
- **`route-artifact-name` 只在显式配置时上传**：本仓库 `session.yml` 已配置（`route-fields`），外部调用方默认没有制品。
- **job 超时**：调用方 `timeout-minutes` 必须大于 `session-minutes`，否则会话会被作业超时中断，且没有机会输出结束状态。
- **可复用工作流的 job 上限固定 55 分钟**：`jobs.<id>.timeout-minutes` 不接受算术表达式，因此 `session-minutes` 请勿超过 45；需要更长会话请用 Composite 自行设置 job 超时。
- **SSH 失败尝试上限不在 runner 侧**：访客认证由中继与 runner 授权清单在认证阶段裁决，runner 只看到中继日志的 `Client joined` / `Client left`，统计不到错误公钥（2026-11-09 实测：2 次错误公钥后 `unauthorized public key` 计数仍为 0）。防爆破需在 `uptermd` 或前置网关做。

## 7. 常见失败与排查

先看日志里的阶段名，再按下面的顺序定位。

| 阶段 | 含义 | 排查顺序 |
| --- | --- | --- |
| `precheck` | 输入或仓库变量缺失、`session-minutes` 非法、运行器缺命令 | 对照第 2 节表格补齐 |
| `fetch-keys` | 取不到 `ssh-user` 的公钥 | 该 GitHub 用户是否登记 SSH 公钥；token 是否能读公开接口 |
| `install-client` | 客户端下载/校验和/解包失败 | 出网是否被拦；版本是否为 `v0.41.1` |
| `start-session` / `linking` | 反连中继失败或会话未 ready | known_hosts 格式、中继端口、uptermd 是否在跑 |
| `parse-connection` | 连接串里取不到登录名 | 客户端版本是否被替换过（键名契约按 v0.41.1） |
| `shared-terminal` | 托管 tmux 未起来 | runner 是否缺 `tmux` |
| `direct-install` / `direct-deps` / `direct-sudo` | Tailscale 装不上、缺命令或没有免密 sudo | 出网是否可达 `tailscale.com`；runner 是否为 GitHub 托管（免密 sudo） |
| `tailscaled` / `tailscale-up` / `authkey` | 守护进程未就绪、30 秒内未加入 tailnet、未传 auth key | key 是否过期/带 `tag:actssh-runner`；ACL 是否允许该 tag；runner 出网与 UDP 41641 |
| `tailnet-address` | 未取得 `100.64.0.0/10` 地址 | `tailscale status` 是否已登录；key 是否有效 |
| `direct-sshd` / `direct-user` / `direct-keys` / `direct-hostkey` | 直连 sshd 启动失败、无非 root 登录用户、授权清单缺失、host key 生成失败 | 运行器是否有 openssh-server；登录用户是否与作业用户一致 |
| `bridge-connect` | 反连 `wss://.../runner/<id>` 不通 | nginx `/runner/` Upgrade、`bridge-base-url` 协议与路径 |
| `bridge-register` | 中继拒绝注册（同会话已有 runner） | 是否重复启动桥接；会话 id 是否已被占用 |
| `bridge-admission` | 准入子进程起不来或异常退出 | 依赖是否装齐（`websockets` / `fido2`）、允许清单是否为合法 JSON |
| `session-wait` | 结局不可知或超时 | `upterm session wait` 返回 125；会话状态是否仍为 ready |
| 浏览器侧 | 页面 404 / 证书告警 / 注册超时 | 先看第 3.3 节三条验证，再看浏览器是否有平台认证器 |

网页通道失败**不会**中断作业，SSH 通道不受影响；日志里会有一条 `::warning::网页通道不可用（<阶段>）`。

直连失败同样**不会**中断作业：日志里是 `失败[阶段 <direct 阶段>]：…；直连不可用，按设计回落中继` 与 `::warning::`，随后 `path_mode=relay`、`session_id` 不变。

## 8. 版本与标签

- `v0.1.0`：首个可用版本（Composite Action + 可复用工作流）。
- `v0.3.0`：新增 Tailscale 直连路径（`direct-mode` / `tailscale-auth-key` / `direct-ssh-port`），以 `path_verified` 区分真直连与 DERP。
- `v1`：移动标签，指向最新的 `v0.x` 兼容版本。
- **锁定到具体 tag 或 SHA，不要用浮动分支**：


## 9. 输入与输出速查

inputs（两种接入方式同名）：`ssh`、`relay-host`、`relay-port`、`web-base-url`、`bridge-base-url`、`known-hosts`、`ssh-user`、`session-minutes`、`idle-minutes`、`allowed-credentials`、`credential-id`、`upterm-version`、`action-upterm-ref`、`direct-mode`、`tailscale-auth-key`、`direct-ssh-port`、`route-artifact-name`、`route-artifact-retention-days`。

| 输入 | 默认 | 说明 |
| --- | --- | --- |
| `session-minutes` | `45` | 会话最长存活分钟数 |
| `idle-minutes` | `10` | 无人连接超过该分钟数即结束会话（SSH 与网页合计）；不得大于 `session-minutes` |
| `direct-mode` | `none` | `none` 只用中继；`tailscale` 建立直连面 |
| `tailscale-auth-key` | 空 | 调用方 Secret 传入的临时 auth key；只从环境读，不打印不落盘；缺失即回落中继 |
| `direct-ssh-port` | `2222` | 直连 sshd 端口（只绑 tailnet 地址），也是 `direct_endpoint` 的端口段 |

outputs（9 个，数量与名称不变；直连条件字段只在日志与摘要中输出，不新增 output）：

| 输出 | 说明 |
| --- | --- |
| `session-id` | 会话标识；`ssh: false` 时为 `none` |
| `ssh-user` | SSH 登入名：直连时为专用非 root 用户名（无冒号，通常 `runner`）；中继时为含嵌入式路由后缀的 `<session_id>:<节点编码>` |
| `relay-host` | 中继主机 |
| `relay-port` | 中继端口 |
| `web-url` | `https://<站点>/t/<session_id>` |
| `pubkey-fingerprint` | 允许登入的公钥指纹，逗号分隔；`ssh: false` 时为 `none` |
| `expires-at` | 预计到期时间（UTC） |
| `pubkey-credential-id` | WebAuthn 凭据标识或 `unset` |
| `path-mode` | `relay` / `direct` / `disabled` |
